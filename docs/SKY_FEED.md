# 天空气球流 — 排布 / 抽样 / 上升 的底层设计（必须遵守）

> 这份文档是"记忆"。**任何改动气球场（scene.js / 气球 CSS / `/api/bubbles` 列表）之前，先读这份文档**，改完回来核对每一条是否仍然成立。这是与用户反复讨论后定下的规则，用来防止"修一个忘一个"。
>
> 相关文件：`public/js/scene.js`（气球场 `createWhisperWorld`）、`public/css/style.css`（`.lantern*`）、`functions/api/bubbles/index.js`（发牌 API）、`public/js/app.js`（拉取 / 作者置顶 / 定时刷新）。

## 0. 一句话目标
天空是**给人读、给人点**的。核心不是沉浸感本身，而是"让每条悄悄话都有机会被某个人看清、点开、回应"。沉浸感（层次、飘动）服务于这个目标，不能盖过它。

## 1. 发牌：每台设备看到不同的加权随机样本
- `/api/bubbles`（列表分支）**每次请求返回一份随机抽样**，不是"最新 N 条"。
- 每次请求重掷 `RANDOM()` → **不同的人 / 不同的刷新看到的气球都不同**（这是产品护城河：人越多，全库被看到的越多）。
- 随机键上叠加权重（越小越容易被选中，`ASC` + `LIMIT`）：
  - 热帖（`warmth` 回复多）更容易出现；
  - 新帖（24h 内）加权；
  - **0 回复的帖子专门加保底权重**（最需要被第一个接住 —— 产品灵魂）。
- 抽样逻辑封在 API 后面，规模再大可换更省的抽样法（随机键区间 / 分桶 / 曝光加权）而**不动前端**。

## 2. 前端是"一条河"，不是"一堆常驻循环"
- 屏上**只保留有限个气球**（`poolCap()`：手机约 14、桌面约 20），不是把整副牌全渲染 → 不会挤成一坨。
- 每个气球从服务端发的这副 `deck` 里**一条条取内容**；飘出顶部后**接上牌堆的下一条**，从底部重新升起。
- 一小把在看，整副牌随时间轮换过去。所有气球（含最远最小的）**都能点开**。

## 3. 抽到顶要换"新气球"，不要把老的拎回来循环
- 一副 `deck` 全部发完一轮后，**立即向服务端再要一份新样本**（`onNeedMore` 回调 → `loadWhispers`，带节流），换进来。
- 另有定时兜底刷新（约 90s）。
- 目的：用户盯着看时，从底部升上来的应当是**新抽到的**气球，而不是同一批在原地循环。

## 4. 必须有 3–4 层纵深（层次感 / "城市感"）
用**离散的 4 个深度层**（不是一条连续均匀分布，否则容易糊成一层）：

| 层 | z 范围 | 视觉 | 权重 |
|---|---|---|---|
| 远（背景） | 0.04–0.16 | 很小的暗点、带轻微虚焦、最慢 | 3 |
| 中远 | 0.30–0.46 | 较小、偏暗 | 3 |
| 中近 | 0.58–0.76 | 中等、清楚 | 4 |
| 近（前排） | 0.88–1.00 | 大、亮、最快 | 3 |

- 每次 `seatDepth` 按权重**随机落入某一层**，再在层内抖动 z。→ 保证每一层随时都有球，**远处永远有小点点**。
- 缩放：`scale = 0.26 + z*1.24`（远 ~0.3× 是小点，近 ~1.5× 大而可读）。
- 透明度：`0.38 + z*0.62`；远层轻微 `blur`。

## 5. 上升速度按层不同（错落有致）—— 关键
- **近的快、远的慢**：`rise = 0.05 + z*0.30`（远 ~0.05 慢，近 ~0.35 快）。
- 不能所有层一个速度一起走，那样是"一张纸在平移"，没有立体感。
- 整体基调仍是"缓缓上升"，只是分层拉开快慢。

## 6. 手机上要更宽、可左右拖，避免重叠
- `worldW = max(视口宽, 气球数 * ~100)` → 手机上是好几屏宽，**可左右拖**（视差：近层拖动多、远层几乎不动）。
- 桌面屏本来就宽，够铺开；手机靠"更宽 + 可拖 + 分层"三者一起避免挤在一起。

## 7. 作者必看自己
- 发帖成功后 `whisperWorld.pin(自己的帖)` → 把它插到队首，最靠近顶部的气球立即从底部带着它重升，作者几秒内一定看到自己的球。
- **⚠️ 光有球不够，要先看到"字"。** 关掉确认框（`releaseMyWhisper()`）时**先 pin，再 `openDetail(id, null, mine)`**：阅读视图直接铺开刚写的那段话，跟点开一个气球一模一样，作者能马上把自己写的读一遍。用户原话："发完之后马上就变成气球了，有时候还要找一下才找得到，这样不好。"
  - 只加一个带光圈的球是**不够**的——一片点里的一个点，还是要找。这条提过两次才改，别再退回去。
  - 顺序不能反：pin 在前，所以关掉阅读视图时球已经在天上飘着，读完一遍不损失任何东西。
  - `openDetail` 传 `known`（就是刚发的那条），从点击到出字之间没有 `await`；`rect` 传 `null`，因为这不是从某个球上放大出来的。

## 7b. 打开一条悄悄话时，整片天空停住（Quiet Mode）
> 用户实测反馈:"后面气球一直在上升,看长内容的时候不舒服。"

- `openRead()` → `whisperWorld.freeze(true)`,`closeRead()` → `freeze(false)`。**气球全部停在原地,也不再放新球**;背景视频照常播放,正文照常缓缓上推(点一下暂停的功能保留)。
- **停,不是变淡变慢。** 慢下来的气球仍然是"眼角有东西在动";停住是读者真的能察觉到的那一下。这是产品决定,不要自作主张改回渐变淡出。
- **⚠️ 必须冻结的是场景自己的时钟(`animTime`),不能用 `performance.now()`。** sway / bob / 深度呼吸都是 `sin(time * ...)`,如果时钟照走,读完一分钟再关闭,整片天空会瞬间跳到一分钟后的相位——看起来就是"炸一下"。
- **⚠️ 解冻时必须把 `lastT` 清零**,否则第一帧的 `dt` 是整段阅读时长(虽然被 clamp 到 50ms,仍然是肉眼可见的一抖)。
- **⚠️ 不能只降 `rise` 不降生成节拍。** 节拍(`spawnAcc` / `beat`)是按平均飞行时间算的并会朝目标数量纠偏:只放慢上升而照原速放新球,屏上气球会**越读越多**,和目的正好相反。现在的做法是整个 `frame()` 直接 return,两者一起停。
- 副作用(好的):阅读时不再往 DOM 写任何 transform,**阅读态反而是手机上最省电的状态**。
- 已核对仍然成立:§1 抽样、§2 河流上限、§3 换牌(冻结期间不回收也就不请求新牌,90s 定时刷新只换 `deck`、不会让画面动)、§4 分层、§5 分层速度(时钟停了,层间比例不变)、§6 拖动(`pointerdown` 只挂在 viewport 上,阅读层盖住它,所以冻结期间 `panX` 不会偷偷漂移)。

## 7c. 天空要铺满整块屏幕（`--bleed`，两个"高度"别搞混）

> 用户实测反馈（改了三次才对）："下面还有黑色的呀，还是不是满屏的呀。"

手机上装成主屏幕 App 之后，刘海和底部小横条那两块必须也是天空，不能出现任何一条边。

- **`<html>` 必须有背景色**（`#05060f`）。它是"画布"，是**唯一**能画到排版视口之外的东西，其他层全是 `position: fixed`，怎么撑都出不去。不设就是白的——最早那条白边就是它。
- **⚠️ 满屏层的盒子不要"算"，要"溢出"。** `top: 0` 和 `100vh` 在主屏幕 App 里到底指什么，**同一台手机的两次安装量出来的结果不一样**：一次是"起点在状态栏下面 + `100vh` 是整屏"（顶部留 62pt 黑边），另一次是"起点在真正的顶 + `100vh` 是整屏减掉两头"（底部留 62pt 黑边）。所以任何按 `100vh` + 安全区推出来的精确盒子，在其中一种情况下必然是错的。现在的做法是 **`--bleed: 120px`，上下各多出 120px**，比任何手机的最大安全区（62pt）都大。
- **只上下溢，绝不左右溢。** 气球世界 `#world` 是定位在 `#lanterns` 里面的，左边多出 120px 会让**整片天空的气球一起往左移**。
- **不参加溢出的两个**：`#scene`（湖面。`HORIZON` 是它高度的比例，变高水平线就跑了；它保持精确盒子，由溢出的 `#sky-bg` 在背后兜住两条边）、`.read-overlay`（透明，而且里面是滚动的正文，移了就是移字）。**带按钮的层一个都不许加进来。**
- **⚠️ scene.js 里从此有两个"高度"，用错哪个都出事**：
  - `skyH()` = `#lanterns` 自己的高度 → **出生和死亡**用它（`it.y = skyH() + 8`）。用 `window.innerHeight` 的话，新气球会在**离屏幕底部 120px 的地方凭空出现**。
  - `seenH()` / `seenTop()` = 看得见的那一块 → **密度**用它（`computeCadence` 的 `visibleSpan`、`onScreenCount`）。把溢出那 240px 也当成"屏上"，会比 §9 调好的密度多要约四分之一的气球。
  - `initScene` 的 `resize()` 量 `canvas.clientWidth/Height`，**不能**量 window 再写回行内高度——那会把 CSS 覆盖掉。
- 改完实测（忽略开头 30s 播种，只数视口内）：手机 9–14，桌面 16–21，与 §9 记录的区间一致。

## 8. 待办 / 以后可做（别忘）
- 规模到千万级时：把"全表随机抽样"换成可扩展抽样（随机键区间扫描 / 分桶洗牌 / 按曝光次数加权保覆盖）。API 形状已为此预留。
- 飘带文案（`ribbon1` / `ribbonMany`）上线前中英定稿。
- "少露优先"（least-shown）曝光加权，进一步保证海量下的长期覆盖均匀。
