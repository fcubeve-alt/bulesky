# APP_PRD_V2 工程回应

> 针对 `docs/APP_PRD_V2.md` 的逐条工程意见。**结论先行**:方向我同意,
> 但**有一件事必须排在所有 P0 前面,否则这一轮做出来的删除和分享都是假的**。
> 讨论定下来的结论要写回 `docs/ROADMAP.md`,那边才是最终依据。

## 一、必须先解决:今天这个站没有"作者身份"

现状(`migrations/0003_person_codes.sql`、`functions/api/bubbles/index.js`、`public/js/app.js`):

- `bubbles.code` 是**用户自己取的公开名字**,不是密码,而且**故意去掉了 UNIQUE**——一个名字下可以有很多条。
- "找一找"是 `GET /api/bubbles?code=xxx`,**任何人输入这个名字,就能拿到该名字下的全部气球**。
- 客户端拿到结果后直接 `rememberMyBubble(b.id)`,把它们记成"我的"。
- 所以现在的"我的内容"= localStorage 里的一个 id 列表,**服务端一无所知,也无法验证**。

这意味着 PRD 里的 P0-1(删除)、P0-3(只分享自己的)在今天的结构上**做不了**:
猜到或看到别人的名字,就能删掉别人的气球、把别人的故事当成自己的分享出去。
Apple 审核里的"阻断滥用者"同样落不了地——没有任何可以封的东西。

**建议方案:匿名作者令牌(不做注册)**

- 发布时服务端生成一个高熵密钥 `author_secret`,**只回给这一次的客户端**,存 localStorage(App 端进 Keychain);
  数据库只存 `author_hash = SHA-256(secret)`。
- 删除/分享/My Sky 全部改成**带令牌请求**,服务端比对 hash。客户端的 localStorage 只做展示,不再是权限依据。
- 给用户一个可导出的**恢复码**(就是那串 secret 的可读形式),文案:"想在别的设备找回你的气球,请保存这串字符"。
  丢了就找不回——这与产品的匿名调性一致,也不需要邮箱/账号。
- 现有那些老气球没有 token:**只在本机 localStorage 里认领过的,允许一次性领取令牌**;其余保持只读。
  这条要写清楚,是历史包袱,不是设计。
- 名字(`code`)保留原样,但**降级成展示用的署名**,不再当身份用。"找一找"应改为只列出内容、不再自动认领。

这一项我建议叫 **P0-0**,先于 PRD 的所有 P0。它是删除、分享、My Sky、封禁四件事共同的地基。

## 二、我同意、且现有结构直接支持的部分

- **收藏只存引用**:新建 `saves(author_hash, item_type, item_id, created_at)`,查询时 join 内容表并按状态过滤。
  作者删除后自动失效,天然满足"不产生永久副本"。
- **`content_status` 取代现在的 `hidden` 布尔**:`active / hidden / deleted / moderation_hold`。
  现在 `hidden` 只有 0/1,举报隐藏和作者删除混在一起,后台分不清。迁移写成 `hidden=1 → 'hidden'`。
- **举报后台队列**:`reports` 表现在不存在,举报只是 `report_count + 1`(`functions/api/report.js`)。
  按 PRD 建的队列表是净增量,不动现有的"AI 判断 + 3 次兜底"两条独立隐藏路径(见 ROADMAP §7c)。
- **别人的故事上不出现 Share 按钮**、**长文本分享片段 + 深链**、**核心体验免费**:完全同意,不展开。
- **权限判断全部放服务端**:同意,而且这是 Web/iOS/Android 共用的唯一办法。现在有几处判断在 localStorage,要搬。

## 三、我有不同意见的部分

### 1. 不要一次加 10 个权限字段

PRD §12 列了 `share_allowed_by_owner` / `external_feature_allowed` / `commercial_use_allowed` /
`tts_onsite_allowed` / `audio_status` 等。**这一轮只需要三个**:`author_hash`、`content_status`、`deleted_at`。

- `tts_onsite_allowed`:站内 TTS 是 Terms 层面的默认许可,**每条内容一个开关等于给每个用户一道选择题**,
  而这个产品的界面原则是不给正在难过的人出选择题。
- `commercial_use_allowed` / `external_feature_allowed`:今天没有任何代码会读它们。等真的要办官方社媒/周边时再加,
  那时才知道字段该长什么样。
- `audio_status`:`voice_chunks` 里有没有行就是状态,不需要第二个真相来源。

留空字段的代价不是磁盘,是**以后每个人都要猜它到底生效没有**。

### 2. 分享卡不要在服务端渲染

Cloudflare Pages Functions 里没有 canvas,图片合成要么上 Browser Rendering(要付费计划、慢、按次计费),
要么外挂渲染服务。**第一版在客户端用 `<canvas>` 画**:背景图 + 文字排版 + 品牌 + 短链,导出 PNG,
走 `navigator.share` / 下载。零成本、零延迟、离线可用,而且和现在纯静态前端的结构完全一致。

### 3. 9:16 视频我建议推到 P2,甚至先不做

- Workers 上跑不了 ffmpeg。真做只有两条路:**外部渲染服务**(有钱、有排队、有存储和流量账单),
  或**客户端 `MediaRecorder` 录 canvas**(免费,但只能前台、时长受限、机型差异大、iOS Safari 常年有坑)。
- PRD 自己也说"传播逻辑是分享一个最有力量的片段 → 链回原故事"。**分享卡 + 深链已经覆盖了这个逻辑**,
  视频带来的增量传播,和它带来的第一个成本失控风险不成比例。
- 建议:先上分享卡,**用真实数据看有多少人分享**。分享卡的分享量起不来,视频也不会救它。

### 4. My Sky 与"匿名"是有张力的,要主动设计

把"我写过的 / 我收藏的 / 我点过的灯 / 我收到的回应"聚到一处,等于**第一次在这个产品里造出了个人档案**。
一旦它存在服务端,就要承担导出、删除、跨境隐私这些义务;而这个站的价值恰恰是"没人知道我是谁"。

建议:**My Sky 的索引尽量留在本地**,服务端只保存"令牌 → 内容 id"的最小引用,
不存浏览历史、不存偏好、不做推荐。这样账户删除等于删掉几行引用,合规和调性都保得住。

### 5. 封禁:没有账号,只能做到"提高成本",不能做到"挡住"

令牌可以重发、IP 会变。诚实的做法是**分层**:发布速率限制 + 内容过滤 + 令牌级封禁 + 影子隐藏
(被封的人自己看得到、别人看不到,不给他即时反馈去换设备)。
Apple 要的是"有可执行的机制",这套够;但不要在 Terms 或后台里写成"我们能阻止滥用者"。

## 四、结构上真正该动的一件事:音频从 D1 搬到 R2

线上实测(`?probe=1`):55 条朗读、**9.3MB 音频存在 D1 里**,而 D1 同时是气球列表和阅读页查的那个库。
ROADMAP §7f 已经记过一次教训:音频把整站拖慢,根源就是它和内容共用一个库。
App 上线后条数会数量级增长,**这是唯一一个现在不动、以后一定要付更大代价的结构问题**。

建议:`voice_chunks` 迁到 R2(对象存储),D1 只留 `hash → key` 的索引。分享卡/视频将来也放 R2。
这件事和身份改造互不干扰,可以并行。

## 五、App 技术路线:建议 Capacitor,不要重写

现在是纯静态前端(`public/`)+ Pages Functions,没有构建步骤、没有框架。

- **Capacitor**:现有页面几乎零改造直接进壳,再按 PRD 的要求补原生能力——系统分享、触觉、通知、
  Keychain 存令牌、状态栏/安全区。**这不是 WebView 套壳**:Apple 拒的是"只有网页、没有移动端价值"的壳,
  PRD §2 列的那些正是要补的东西。
- **React Native / Flutter 重写**:等于把 `scene.js` 的天空、`ambient.js` 的音频、Listen 那一整套 iOS 手势
  和 Web Audio 的坑**全部重踩一遍**,而这些坑在 ROADMAP §7e/§7f 里是有名字的。我不建议。

## 六、我建议的执行顺序(与 PRD §20 的差异)

1. **P0-0 作者令牌**(新增,排最前)。没有它,2 和 3 都是假的。
2. P0-1 删除(气球 + 回复),连带删掉 `voice_chunks` 里的音频、失效分享深链。
3. P0-5 举报队列 + 后台处置 + `content_status`。**这条和上架强相关,建议早做**。
4. P0-2 收藏 / My Sky(先只做 My Balloons + Saved)。
5. P0-4 分享卡 + 精选片段深链(客户端 canvas)。
6. 音频迁 R2(可与 1–5 并行)。
7. Capacitor 外壳 + 原生分享/触觉/通知 → 提交商店。
8. 视频、Sponsored Sky、周边等,等真实数据。

**理由**:PRD 把"收藏/My Sky"排在举报治理前面,但**能不能上架取决于治理,不取决于收藏**;
而删除和分享取决于身份。所以顺序改成"身份 → 删除 → 治理 → 收藏 → 分享"。

## 八、Capacitor 是什么(给非工程视角的解释)

做 App 有三条路,差别在于"现在这个网站的代码还能不能用":

| 路线 | 做法 | 现有代码 | 工作量 | 上架风险 |
|---|---|---|---|---|
| 网址壳 | App 里开一个浏览器窗口,指向 cubewithin.com | 全部保留 | 1 天 | **会被 Apple 拒**:没有移动端价值 |
| **Capacitor** | 把网页文件**打包进 App 装在手机里**,再给它开一扇门去调用手机功能 | 全部保留 | 几天 | 低,前提是补上原生能力 |
| 原生重写 | 用另一套语言(React Native / Flutter)把天空、音乐、朗读全部重做 | **几乎全部作废** | 2–3 个月 | 低,但坑要重踩一遍 |

**Capacitor 和"网址壳"的区别**(这是 Apple 真正在看的):

- 网址壳 = 打开一个网址;没网就白屏,没有任何手机能力。
- Capacitor = 代码**装在手机本地**,有自己的图标和启动画面,**没网也能打开**,并且可以调用:
  系统分享面板、震动/触觉、推送通知、**钥匙串(正好用来存那串作者令牌,比浏览器安全得多)**、
  状态栏与刘海安全区、相册保存(分享卡)。

Apple 拒的是"没有移动端价值的壳",不是 WebView 这门技术本身——很多大厂 App 内部也是混合的。
PRD §2 列的 My Sky、收藏、Listen、触觉、系统分享,正好就是把它从"壳"变成"App"的那些东西。

**代价要一起说清楚:**

- 复杂动画不如原生流畅。这个站的天空是 CSS/Canvas 飘气球,压力不大,但机型很旧的手机会有差别。
- 上架 iOS 要在 macOS 上打包 —— 但**不需要自己有 Mac**,见下一节。
- 每次改网页要重新打包发版;不想发版的话可以让部分内容走线上加载,但那部分就没有离线。

**为什么不建议重写**:`scene.js` 的天空、`ambient.js` 的音频图、Listen 那一整套 iOS 手势与 Web Audio 规则,
在 ROADMAP §7e/§7f 里每一条都是踩出来的(`element.volume` 在 iPhone 上无效、点击到出声之间不能有 `await`、
装饰不能变成静音……)。重写等于把这些坑按同样的顺序再踩一遍,而换来的只是"原生"两个字。

## 九、没有 Mac 怎么上架 iOS(站主全程 Windows)

**结论:一台 Mac 都不需要,连借一次都不用。** 上架分四件事,只有"打包"那一步需要 macOS,而那一步可以租云端的 Mac。

| 步骤 | 在哪做 | 需要 Mac 吗 |
|---|---|---|
| 注册 Apple Developer Program($99/年) | 网页 / iPhone 上的 Developer App | 否 |
| 把网页打包成 iOS 安装包 | **云端构建服务**(它那边跑真的 Mac) | 否 |
| 证书 / 描述文件 | 用 App Store Connect API Key 让 CI 自动生成 | 否(2019 年之后就不用了) |
| 填资料、传截图、提交审核 | 网页 appstoreconnect.apple.com | 否 |
| 自己在 iPhone 上试用 | TestFlight(App Store 里装) | 否,但**需要一部 iPhone** |

**推荐 Codemagic**:有现成的 Capacitor / Ionic 流程,托管 App Store Connect API Key、自动处理证书,
直接发到 TestFlight 和 App Store,有免费额度(具体分钟数以注册时页面为准)。
备选:GitHub Actions 的 macOS runner(仓库已经在 GitHub,但 macOS 分钟按 10 倍计费)、Capgo Cloud Build。

**⚠️ 2026-04-28 起,提交到 App Store 的包必须用 Xcode 26 以上构建。** 云端服务会跟进版本,自己维护构建机就要自己升。

**⚠️ 真正要先确认的不是 Mac,是付款**:Apple Developer Program 的 $99/年只能刷卡,
和 ROADMAP §7f 里"买不到的 provider 不是 provider"是同一类问题 —— 先确认这张卡能付,再谈上架时间表。
Google Play 是 $25 一次性,同样要确认。
