## 0. 一句话定位
不是"树洞(Tree Hole)",而是一个**"让情绪漂流、让善意找到它们的地方"** —— 由星空 / 音乐 / 气球 / 海浪组成的**情绪空间**。核心力量感:*"我把它放出去,希望有陌生人接住它。"*

**现阶段首要目标不是赚钱**,而是证明"这个世界真的会有人回来"——关注**留存、回访、真实的安慰感**。

## 2. 情绪交互机制(产品的灵魂)

### ①+④ 气球"飘带"= 陌生人停留 / 陪伴式提示 ⭐(用户核心想法)
飘动的气球**下方挂一条小飘带**,文字随该气球的**回复数(warmth)**变化,每个气球内容不同、随风飘动:
- **✅ 决定:0 回复 → 不挂飘带**(保持天空干净;避免上线初期一片"还没人回复"的冷清杂乱)。把"成为第一个接住 TA 的人"的**邀请放进点开后的阅读页**(0 回复时高亮回复按钮 + 一句温柔邀请),在"人家正在读"的最佳时机转化。
  - (备选,未采用:只让最靠近屏幕中心的那一个空气球短暂显示邀请。)
- **≥1 条回复 → 挂飘带**:`已经有 N 个人为 TA 停留` / `有陌生人回复了 TA`(正向温暖信号)。
- 语气是"陪伴感"而非"评论数"。避免冷冰冰的"58 条评论"。
- **实现**:`warmth`(=非隐藏回复数)已随 `/api/bubbles` 列表返回,`scene.js` 渲染气球时即可读取——**无需改后端**。飘带是 `.lantern` 下方的一个 DOM 元素 + CSS。

### ② 传递微光 Passing Light
- **✅ 决定:微光按钮放在"点开阅读页之后"**(读完才能点,像看完点爱心;没读过不该能点)。位置:阅读页底部那排,紧挨"留言",放一个 **"留一点光 ✨"**。
- 点一下 → 气球柔光 +1 档、**不显示数字/不排名**;**每台设备每个气球只能留一次**(点完变"已留下微光",localStorage 防刷)。
- 意义:给"读了、我在,但不想打字"的人一个**零负担**的温柔回应。
- **实现**:后端加 `lights` 计数字段 + 一个自增接口(带简单防刷);前端把光晕强度 `--glow` 与 `lights` 挂钩。

### ③ 气球随回复"成长"(视觉隐喻)
不是单纯变大,而是**光影叠加 + 颜色渐变**:
- 光影:`初始` → `1 条:一个小光点` → `5 条:几只慢飞萤火虫` → `大量:柔和星光环绕`。
- 颜色(治愈隐喻):`淡蓝(初始/忧郁)` → `月白` → `暖金(被治愈)`。
- **实现**:纯前端,按 `warmth`(+ `lights`)分档切换特效与配色。

### ⑤ 首页每日暖句
- 首页飘一句**每天变化**的温暖话语(如 *"You don't have to carry everything alone"*),免登录即有新鲜感与慰藉。
- **实现**:一组句子,按日期取一句,纯前端。

### (附)发布 / 评论界面重设计 —— 用户当前最在意
现有底部小弹窗体验局促。目标:像成熟平台的评论体验。
- **回复**:气球阅读页底部**常驻输入栏**,点开顺滑展开;输入框上方一句**温柔引导**("如果这是你的朋友,你会怎么说?");发送键醒目;署名选填收起。
- **发布**:干净大输入区、舒服行距、情绪类型(倾诉 / 许愿)清楚切换、字数提示低调、顶部一句引导语。
- 气质:更大留白、更柔动效,契合"情绪空间"。

## 3. 善意守护 Kindness Guard(审核)
**核心原则:允许痛苦,禁止伤害(Pain is welcome. Harm is not.)**——疗愈平台,不是纯言论自由平台。
- **对表达宽容**:思念 / 失恋 / 孤独 / 绝望 / 后悔等负面情绪都接纳(那是在表达自己)。
- **对伤害零容忍**:针对他人的辱骂 / 人身攻击 / 嘲笑 / 霸凌 / 歧视 / 诅咒 / 骚扰,严拦。

机制(四层):
1. **敏感词过滤**(已部分实现:辱骂 / 联系方式 / 危机词 `src/filters.js`)。
2. **AI 语义识别**:识别"没脏话但有攻击/嘲讽/霸凌"的内容 →(需接 AI 服务,见开放问题)。
3. **发送前温柔提醒**(不直接拦):`这里是一个以善意为原则的空间,你愿意换一种表达方式吗?`
4. **人工复核**:涉及生死 / 违法 / 举报。
- **命名**:对外叫 **Kindness Guard(善意守护)**,不叫"内容审核"。
- **交互温柔引导**:回复框上方提示"一句真诚的话,可能会陪伴一个陌生人很久"。
- **《社区原则》页** + 首页善意声明。
- 护城河:一种"永远善意、没有攻击"的回复文化——最难被抄。

## 4. SEO 与隐私:公开品牌 + 私密内容
架构分"前面的世界(公开)"与"后面的世界(私密)"。
- **可收录(只服务官方页)**:首页 / About / FAQ / Help / Blog。
- **禁止收录(用户内容)**:所有 UGC 加 `<meta name="robots" content="noindex,nofollow">`,`robots.txt` 精准 `Disallow` 用户路径,`sitemap` 只放官方页。
- **首页信任承诺**:*"Your stories remain private and are not indexed by search engines."*
- 版权:每个故事归作者,默认**禁止他人转载**;仅提供**作者一键分享**(已做:分享=链接、录像仅本人)。
- ⚠️ **结构前提**:当前整站是单页 App(只有 `/`),没有 About/Blog 等独立页面。本模块本质是**新建一套官方页面体系**,属子工程 → 放到三期。

## 5. 商业模式(后期,不打扰用户)
保持"干净"氛围,不过早上广告 / 付费墙。梯度盈利:
1. 支持性打赏:**Keep this sky glowing**。
2. **永久气球 Forever Balloon**:付费让思念长留星空。
3. **点亮微光 Leave a Light**:付费支持社区、点亮他人气球。
4. **纪念册 Memory Book(核心收入)**:把用户故事 + 陌生人回应 + 视觉背景整合成 PDF / 实体书(纪念逝者 / 爱情 / 人生记录的强动机)。
5. 公益赞助:心理健康类组织的页脚赞助。

## 7c. 举报与内容安全 —— ✅ 已完成(2026-08,依《举报与内容安全规则》补充需求文档)

**举报入口**:气泡本体一个(阅读页底部那排,`#read-report-btn`),每条回复各一个(`.reply-report`);两边计数互不影响。一台设备对同一条只能报一次(`localStorage` 的 `reported_items`,键形如 `bubble:12` / `reply:34`),报完变灰显示"已举报"。**不做二次确认**——多一步只会少收到举报。

**隐藏规则(两条路,满足任一即隐藏)** —— `functions/api/report.js`:
1. **AI**:每一次举报(不只第一次)都跑一次 Workers AI 二分类(`@cf/meta/llama-3.1-8b-instruct`,`[ai]` binding 在 `wrangler.toml`)。判定违规 → 立即隐藏。
2. **人数兜底**:累计 3 次举报 → 强制隐藏,不管 AI 怎么说。
   - AI 不可用 / 报错 / 没绑定 → **fail open**(当作没问题),举报计数和 3 次兜底照常工作。**绝不能让 AI 故障把举报功能一起弄坏**。
   - 成本:只在有人举报时才调用,量级≈举报数,可忽略。

**隐藏后**:对所有人不可见,**包括作者本人**(防"平台留着辱骂给当事人看"的截图风险)。但暗号查询里**不静默消失**,列一行"这条内容因违反社区准则已被处理"(`removedNotice`,5 语),不可点。后端在 `/api/bubbles?code=` 与 `/api/bubbles/by-code/[code]` 两处都做了 redact。

**危机提示**:`#crisis-banner` 在"倾诉"发布页**常驻**,不做关键词触发式弹出(命中才提示是事后干预,且规避太容易)。文案按 `navigator.language` 走现有 `detectLang()`,5 语之外默认英文;各语言保留本地号码,并统一加一条 findahelpline.com 链接兜住其余国家。

**关键词过滤**:维持现状(英文为主),不扩展其他语言——非英文内容的安全由"举报 + AI 语义判断"兜底,AI 不受语言限制。

**阅读页可暂停**:文字以约 50px/s 上升,62×22px 的举报按钮根本点不中。**点一下正文或某条回复会冻结上升(再点恢复)**,`.read-scroll.paused`。改动前请确认这条仍成立,否则每条回复的举报按钮等于不存在。

## 7d. 博客后台(CMS)—— ✅ 已完成(2026-08)
> 用户要求:"我要在后台可以发博客"。博客从静态 HTML 改为 **D1 + Pages Functions**,写文章不再需要改代码、发版。

- **后台**:`/admin.html`(`noindex` + `robots.txt` Disallow)。列表 / 新建 / 编辑 / 发布 / 撤回 / 删除;Markdown 正文,标题自动生成 URL(可改),摘要选填(留空取第一段)。
- **登录**:单一密码 `ADMIN_PASSWORD`(Pages secret,由 deploy workflow 从 GitHub secret 同步)。密码只用于校验和签名,**不入库、不进 cookie**;cookie 是 `<过期时间>.<HMAC-SHA256>`,两周过期,HttpOnly + Secure + SameSite=Strict(`src/admin-auth.js`)。**没配 `ADMIN_PASSWORD` 时任何人都进不去**(而不是所有人都能进)。
- **前台**:`/blog/`(列表)、`/blog/<slug>`(正文)由 `functions/blog/` 渲染,套用与官方页同一套 `pages.css` 外壳(`src/blog-page.js`);草稿对读者一律 404。`/sitemap.xml` 改成动态,发布即进 sitemap。
- **图片**(2026-08 加):后台「Add image」按钮,或**直接往正文框里 Ctrl+V 粘贴**。图片先在浏览器里用 canvas 压到长边 1600px 再上传(手机照片动辄 3–8MB,而正文栏只有 660px 宽);PNG 压完仍超 500KB 就转 JPEG。存在 D1 的 `images` 表,公开地址 `/media/<id>`,`immutable` 长缓存(一个 id 永远对应同一份字节)。**以后图多了要换 R2,只需换存储,`/media/<id>` 这个地址不变。**
- **图片管理 / 删除**(2026-08 加):后台列表页右上「Images」进图库,每张图显示缩略图、`/media/<id>`、大小、日期,以及**它被哪几篇文章用着**(`WHERE body LIKE '%](/media/<id>)%'`)。删除必须知道这件事——一张图上传后就公开可访问,和有没有文章引用无关;而直接删掉一张正在用的图,只会在已发布的文章里留下一个碎图,后台自己是看不出来的。所以 `DELETE /api/admin/images/<id>` 在有文章引用时**默认拒绝**(`409 in_use`),前端的确认框先把文章标题念给你听,你点确认它才带 `?force=1` 再发一次。**注意 `immutable` 长缓存**:删掉的图,已经看过的浏览器还会拿缓存显示很久——删除只保证不再有新的人看到。
- **Markdown**:`src/markdown.js` 只支持 `##`/`###`/列表/引用/`---`/粗斜体/链接/图片 `![说明](/media/1)`。图片解析必须排在链接**前面**(`![x](y)` 也匹配链接的正则)。**先转义再解析**,链接只放行 `http(s)` 和站内 `/`;JSON-LD 里另外把 `<` 转成 `<`(否则标题里一个 `</script>` 就能越狱)。
- **原来的 3 篇**:源文件在 `content/blog/*.md`,`node tools/gen-post-seed.mjs` 生成 `migrations/0007_seed_posts.sql` 灌进 D1(`INSERT OR IGNORE`,重跑迁移不会覆盖你在后台改过的内容)。改种子文章正常做法是**直接在后台改**,不用动 md。
- **缓存**:文章页 `cache-control: max-age=60` —— 撤回一篇已发布的文章,已经打开过的浏览器最多还能看到 60 秒。
- **`public/_routes.json`**:只有 `/api/*`、`/blog`、`/blog/*`、`/media/*`、`/sitemap.xml` 走 Functions,其余静态资源直出。**新增动态路由记得加进来**。

## 7e. 首屏打开速度 —— ✅ 已修(2026-08)
> 用户反馈:"第一次点开我们的网站……要等一下下几秒钟"。测出来问题**全在背景视频**,和代码、API、气球都无关。

**测量方法**(别靠感觉,`playwright-core` + CDP 限速 4 Mbps / 100ms,iPhone viewport,`serviceWorkers: 'block'` 模拟真·首访):冷启动**一次要下 33–98 MB**,全是 `.mp4`。HTML+CSS+JS 加起来才 0.16 MB。

三个原因,三个改法:
1. **`<video preload="auto">`** —— 等于叫浏览器把整个文件吞下去。改成 **`preload="none"`**;`backgrounds.js` 本来就自己 set `.src` 再 `play()`,不依赖预加载。只有 `prepareNext()` 里把待命层临时设回 `auto`。
2. **`playFirst()` 里立刻调 `prepareNext()`** —— 首屏就并行下**两个**视频抢带宽。改成等当前这条真的 `playing` 之后再等 5s(没触发就 12s 兜底)。
   - ⚠️ 这带出一个坑并已修:视频出错时的 `error` → `advance()` 会切到**还没来得及准备的待命层**,天空变黑。`advance()` 现在会先检查 `standby` 有没有 src,没有就当场 `prepareNext()`。
3. **片子本身就太大**(根因)—— 素材站给的是广播码率:一条 12 秒的河流 1920×1080 **16.4 Mbps / 24MB**,而它是**静音、盖着暗色蒙版、在 390px 宽的手机上**播。`tools/shrink-video.mjs`:长边 1280、CRF 30、去音轨、`+faststart`。**388 MB → 88 MB**,单条均值 8.8MB → 2.0MB,画面在蒙版下看不出区别。幂等,已经瘦的会跳过。
   - **每周抓取的新片必须也过一遍**,否则一周就退回原样 —— 已加进 `fetch-media.yml`(runner 自带 ffmpeg)。

**Service Worker 别碰媒体**:`/video/`、`/music/` 现在直接 `return` 不拦。两个实打实的理由——Cache API 存不了 `<video>` 要的 **206 Partial Content**(那句 `cache.put` 一直在静默失败);而且原来那句 `cache: 'no-cache'` 会**强制每一段字节都回源重验**。这里"不帮忙"就是最快的。

**结果**(同一套测量):冷启动 **33–98 MB → 1.1–4.1 MB**,第一颗气球 ~940ms;第二次访问 ~260–290ms。
> 测量环境的坑:Playwright 自带的 Chromium **没有 H.264**(`DEMUXER_ERROR_NO_SUPPORTED_STREAMS`),所以脚本里"视频播起来了吗"永远是 NEVER —— 那是测试浏览器的限制,不是站点的问题。流量数字仍然有效(浏览器照样把字节下完了才解码失败)。要验证画面得用真机或带专有编解码的 Chrome。

**还没做**:`public/music` 还有 244 MB,单曲最大 18 MB。它只在用户点了音乐按钮之后才下载,所以**不影响首屏**;但对用户流量不友好,想省的话同样可以转 128kbps。

## 7f. 朗读悄悄话(Listen)—— ✅ 已上线(2026-08)
> 用户要求:"点开气球可以选择看文字,旁边有个按钮可以听……**关键是读出来要有感情,像人读的一样**,不是机器读的那种。"

**这个功能的重点不是能出声,是怎么出声。** 一段平板的机器音念"我还是会偷偷跟你说话",比不念更糟。所以选型只看一件事:能不能**被指挥**。

**架构:懒生成 + 永久缓存(这条是硬要求,别改成别的)**
> 用户原话:"绝对不要用户点一次气球,就实时调用一次 AI 生成语音……如果未来有百万、千万个气球,绝对不能每发布一个气球就自动生成音频,那个架构我会否掉。"

发布气球 → **只存文字,不碰 TTS,$0** → 没人点 Listen 就**永远不生成** → 第一个人点 → 查缓存 → 没有才调一次 API → 存库 → 从第二个人起永远播同一份。**成本只随"被听过的不同气球数"增长,和流量、和气球总数都无关。**
- 三条不变量,改代码时必须还成立:①发布路径里**不能出现**任何 `voice`/`tts` 引用;②`/api/voice/<id>` 只能被 Listen 按钮触发,**不能自动播放**;③缓存命中时**一次外部调用都不能有**(包括选音色的那次)。
- 全自动,不需要人工介入任何一步。

**三种声音,由 AI 挑**(用户要求:"我甚至不建议全部都是女声"):`warm_female` / `gentle_male` / `soft_neutral`,映射到 OpenAI 的 `coral` / `ash` / `sage`。挑选跑在 **Cloudflare Workers AI**(举报审核已经在用的那个绑定,几乎免费),**只在缓存未命中时跑一次**——和音频同一份预算。
- **音色故意不进 hash**:音色是"读了文本才知道"的,若进 hash 就得每次查缓存前先分类一遍,等于白花钱。所以 hash 只覆盖 `RECIPE + 模型 + 类型 + 文本`,**实际选中的音色存在行里**(`voice` 列,便于以后调音)。
- 分类器坏掉 → **一律退回 `soft_neutral`**(没绑定 / 抛异常 / 答非所问 / 空回答,四种都测过)。选不出音色绝不能变成"这条读不了"。

**⚠️ 链条从六家砍到三家(2026-08),`CHAIN = ['openai', 'aura', 'melo']`。** 站主的原话:"原来想用的那个专门的模型没有用,eleven 也没有用,现在用的就是 OpenRouter 上那个免费模型 —— 之前那些不用的删掉吧,不要每次播音都一个一个看过来。"于是 **ElevenLabs / 火山引擎 / Gemini 三条腿连代码一起删了**,`git log` 里都在,哪天买了 key 再加回来是"CHAIN 一项 + `available()` 一行 + `speak()` 一个分支"。
- **省下来的时间要说实话**:没配 key 的 provider 本来就在 `available()` 里被跳过,**不花时间**;真正花时间的是**配了 key 却慢慢失败的那种**(Gemini 就是,每条朗读白等一个完整超时)。所以这次删代码主要是少一堆读起来会误导人的东西,速度上只有 Gemini 那一类才是实打实的。
- **Workers AI 那两条(Aura / MeloTTS)留着**,它们不要 key、不要卡,而且只有在中转站失败之后才会被碰到 —— 它们要解决的不是"声音好不好听",是"中转站没额度那天,读者听到的是稍微朴素一点的声音,还是手机自带的声音"。
- **火山引擎是唯一能用支付宝付款的那条路**,删掉的是代码不是这个事实;真要买,从 `git log` 里捡回来比重写快。

**⚠️ 两个"免费档"都撑不起这个功能,这是数字问题,不是 bug。**
| | 免费额度 | 换算成悄悄话(按 300 字/条) | 实测状态 |
|---|---|---|---|
| ElevenLabs 免费档 | **10,000 字符 / 月** | 约 **33 条 / 月** | `401 quota_exceeded`,余 28 |
| Workers AI Aura | 10,000 neurons/天,但 **Deepgram 是合作方模型** | — | `429`,**UTC 日额度重置后近 3 小时仍然 429** |
| **MeloTTS(`@cf/myshell-ai/melotts`)** | Cloudflare 自家模型,走标准免费额度 | 够用 | ✅ 链条底座 |
| OpenAI `gpt-4o-mini-tts` | 无免费档,约 **$15 / 100 万字符** | 约 $0.005 / 条 | ⛔ **不对中国大陆开放,且要外币卡** |
| **火山引擎(豆包)大模型语音** | 新用户约 2 万字符试用 | — | ✅ **支付宝可付**,代码已就绪,只差 `VOLC_APPID` / `VOLC_ACCESS_TOKEN` |

**⚠️ 链条顺序是 Aura 打头,这是一次推翻前提的决定(2026-08)。**
这个功能的前提一直是"要有感情"。等真的接上两个能听指挥的模型(Gemini / OpenAI),站主听完的判断是**不要**:"感情太丰富了,忽高忽低,听着不舒服,要正常的就好"。需求赢过前提。
实测数字也一边倒:

| | 耗时 | 体积 |
|---|---|---|
| Aura | **0.6 秒** | **11,912 字节**(MP3) |
| Gemini | ~9 秒(过载时 17 秒才报 503) | **514,604 字节**(未压缩 WAV,43 倍) |

- **那 43 倍不只是下载。** 每次首听要把它写进 D1、每次重播要从 D1 读出来拼好——**和"点开气球""拉悄悄话列表"用的是同一个库**。于是一条一两兆的音频把**整站**都拖慢了:点气球要等一两秒、音乐要等、连已经生成过的朗读也要几十秒。**站主报的"整站变慢"根源在这里,不在前端。**
- 所以现在是快的、小的、平的那个打头。下面几个是 Workers AI 日额度用完时的后备。**将来要把某个付费 provider 提回最前,改 `CHAIN` 一个词即可——但那会换掉缓存键,全站重新生成一遍,别随手改。**
- **⚠️ 每个 provider 有 20 秒上限**(`ATTEMPT_MS`)。Gemini 曾经花 17 秒才吐出一个 503,那 17 秒读者全程盯着一个看起来坏掉的按钮。谁卡住都要能被放弃,让下一个来说话——这才是"链条"的意义。上限给得宽,是因为长悄悄话本来就合成得久,砍掉真活等于用"慢"换"没有"。

**Gemini(Google AI Studio)—— 目前唯一"不绑卡就有免费额度"的 provider。** 配 `GEMINI_API_KEY` 即用,链条排在 OpenAI 之后、火山之前。它也支持自然语言的表演指示(直接写进 prompt),所以 `DELIVERY` 在这里是生效的——全链条只有它和 OpenAI 做得到。
- **⚠️ Gemini 返回的是裸 PCM,不是能播的文件。** 24kHz / 16-bit / 单声道,mime 形如 `audio/L16;codec=pcm;rate=24000`,**没有文件头**。直接存进缓存 = 一条**永远播不出来**的音频(缓存是永久的,Google 自己的 issue 区一堆人踩)。现在的做法是套一个 44 字节 RIFF/WAV 头,采样率**从 mime 里读**而不是写死。已在真实 Chromium 里用 `decodeAudioData` 验证过能解码。
- 代价:WAV 不压缩,约 48KB/秒,是 MP3 的三倍多。D1 分片(900KB)扛得住,但存储和流量都要按三倍算。

**OpenRouter(可用支付宝充值)—— 目前最现实的一条路。** 它有一个**和 OpenAI 完全兼容的 `/api/v1/audio/speech`**,所以走的就是下面这套 `OPENAI_*` 配置,不需要新代码。三个 secret:
```
OPENAI_API_KEY   = sk-or-v1-...
OPENAI_BASE_URL  = https://openrouter.ai/api/v1
OPENAI_TTS_MODEL = deepgram/flux-tts:free
```
- **⚠️ "OpenAI 兼容"指的是信封,不是内容。** 同一个协议后面挂的是别家的模型,音色名和格式都是别家的:
  - `response_format` 我们默认 `aac`(OpenAI 的 MP3 码率对一个人轻声念太浪费),但**只有 OpenAI 保证支持 aac**。所以非 OpenAI 模型自动改用 `mp3`,这是每家都有的。
  - 音色名不通用。`coral` 对 Deepgram 毫无意义,Flux 的音色是 **Haley / Heather / Priya / Jack / Bruce / Rufus / Drew**。代码里按模型名匹配已知音色表(`RELAY_VOICES`),没匹配上的模型配 `OPENAI_VOICE_MALE` / `OPENAI_VOICE_FEMALE` 即可,不用改代码。
  - `instructions`(表演指示)**只有 `gpt-4o-*` 认识**,Flux 不认。所以走 Flux 时是模型自己的自然表达,`DELIVERY` 不生效——这一条要提前知道,不然又会以为是 prompt 没写好。

**⚠️ OpenAI 支持中转站(`OPENAI_BASE_URL`)。** api.openai.com 不是所有地方都能到,而一个说同样协议的中转站就是"这个 provider 对本项目存在与否"的差别(Azure OpenAI / OpenRouter / 自建也都是这个形状)。配 `OPENAI_BASE_URL` 指过去即可。
- **⚠️ 只有 `gpt-4o-mini-tts` 认识 `instructions`**,而中转站常常只有老的 `tts-1`。给 `tts-1` 发 `instructions` 会直接报错,所以代码按模型判断:认识才发,不认识就安静降级(丢掉表演指示,但仍然出声)。选中转站时**必须先确认它支不支持 `/v1/audio/speech`、有没有 `gpt-4o-mini-tts`** —— 多数中转站只转文字模型。
- **⚠️ 音频格式以响应头为准,不以请求为准。** 中转站可能无视 `response_format` 直接回 MP3,标成 AAC 存进永久缓存就是一条永远播不出来的音频。

**⚠️ 选 provider 之前先问"这个能不能付钱",再问"好不好听"。** OpenAI、Google、ElevenLabs 三家的质量排序毫无争议,但站主没有外币卡、OpenAI 也不对中国大陆开放——**买不到的 provider 不是 provider**。火山引擎排在链条第二位就是这个原因,不是因为它音质第二。这条在评估任何新服务时都要先过一遍。
- 火山引擎接口:`POST https://openspeech.bytedance.com/api/v1/tts`,`Authorization: Bearer;<token>`(**是分号不是空格**,写成空格直接鉴权失败),返回 `200` + body 里的 `code`(成功是 `3000`)+ base64 MP3。**HTTP 状态码不代表成功,必须看 `code`。**
- `reqid` 每次必须唯一(UUID)。
- 音色 id 取决于账号开通了什么,所以 `VOLC_VOICE_MALE` / `VOLC_VOICE_FEMALE` 可以不改代码直接换。

- **ElevenLabs 免费档是"月"额度不是"天",而且只有一万字符。** "读两条就没声了"就是这么来的——不是 bug,是额度本来就只够几十条。**别再把免费档当成一个可以依赖的 provider。**
- **Aura(Deepgram)是合作方模型**,免费额度重置后照样 429,**不要再把它当免费兜底**。真正的免费兜底是 MeloTTS。
- **MeloTTS 只有一种声音,这在今天是优点**:用户抱怨过"昨天男声今天变女声",一个只有一种声音的 provider 不可能漂移。

**⚠️ 声音会变,是缓存 key 的必然结果,不是随机。** `voiceHash` 里含 `RECIPE` 和 `providerFor(env)`:**改 RECIPE 或换首选 provider,全部已缓存的朗读一次性作废**,下次点开会重新合成,而重新合成时本地哈希选的旁白可能和当初 AI 选的不一样——于是"同一条昨天是男的今天是女的"。
- 想要**全站一种声音**,只有一条路:**定下一个 provider 之后,bump 一次 `RECIPE` 让全部重新生成**。在那之前必然是混着的(有几条是 ElevenLabs 女声,其余是 MeloTTS),因为缓存是永久的,谁先被点开就永远是谁的声音。
- 反过来说:**没想清楚要用哪个 provider 之前,不要乱动 `RECIPE`** —— 每动一次,所有人已经听过的声音都会换一遍。
- **ElevenLabs 用 premade 音色,不查账号音色列表。** 这个项目的 key 只有 text-to-speech 权限,`/v1/voices` 会返回 `401 missing_permissions (voices_read)` —— 而**朗读本来就不需要那个权限**,是我为了"挑音色"自己加出来的依赖。premade 音色 ID 是所有账号通用的公开常量,直接拿来念就行。**别再把请求路径接回 `/v1/voices`。**
- **不要为了这种事去让站主改控制台。** 我差点把一串"你去 ElevenLabs 后台勾一下"的步骤丢给他;正确的做法是把这个依赖从代码里去掉。**能在代码里解决的,不要变成对方的待办事项。**
- Workers AI Aura 目前 `@cf/deepgram/aura-1 → 429`(被限流),所以后备这条路现在是断的 —— 但首选能用,而且两个都断时**读者仍然有声音**:退回浏览器自带朗读(见下面那条 iOS 手势的坑)。

> **别再用"某一条气球能播"证明功能好了。** 之前那句"实测 `HTTP 200, 168063 bytes` 真 MP3"是真的,但它是**缓存命中**——同一分钟的失败日志里,每一条没缓存过的都在被拒。从站外看,缓存命中和"合成正常"长得一模一样。`check-sky` 现在从 `/api/bubbles` 取一批真实 id 逐个请求,问的是"**没人听过的那条能不能听**"。

**⚠️⚠️ 那个"神秘的 502"根本不是 worker 被杀,是我们自己的错误说明被边缘丢掉了。**

`/api/voice` 连续多天返回 Cloudflare 那个 16 字节的 `error code: 502`,而失败日志里什么都没多。我据此断定 worker 被平台终止(终止不抛异常、不跑 catch、不 flush `waitUntil`),还把这条写进了文档。**这个判断是错的。**

真正的原因:**Pages Function 返回任何 5xx,Cloudflare 边缘会把 body 换成它自己的错误页**。worker 一直活得好好的,一直在返回写得清清楚楚的 JSON,只是**没有一个字到得了客户端**。所以看起来"没有留痕"——痕其实一直在库里,是响应体被换掉了,前端只能读到"502"三个数字。

**现在这个 endpoint 永远不返回 5xx**:失败也是 `200` + JSON,前端**按 `content-type` 而不是按状态码**判断这是一段朗读还是一句解释。

沿路修掉的另外两个真问题:
- **ElevenLabs 免费档不能用声音库音色**(`402 paid_plan_required`),所以写死 Rachel/Adam 的那版**一次都没成功过**;那"能用两三次"全是旧 provider 留下的缓存命中。改成只挑账号里 `category: premade` 的音色——免费档能用的就是这一类;付费账号可能一个 premade 都没有,那就退回用整份列表,不能把付费用户困死。
- **provider 从"选一个"改成"依次试"**。首选被拒 = 读者听不到,而旁边还挂着一个能用的 Workers AI 绑定。**这里要防的失败不是"声音不够好听",是"没有声音"。**

**几条可复用的教训**:
1. **两个不相干的服务商坏成同一个样子 → 去找它们共用的东西**,不要继续换服务商。
2. **静默降级的功能必须有失败留痕**。Listen 按设计失败就退浏览器朗读,对用户是对的,代价是连着几轮排查手上一点证据都没有——直到加了 `voice_errors` 表 + `?probe=1`,第一次就拿到了确切错误。
3. **"没有证据"本身要先当成一个 bug 查**,不要拿它去支持某个理论。我把"日志里没有"读成了"代码没跑到",于是推出"被平台杀了";实际上是"跑到了、也写了、只是你看不到"。**先确认你的观察通道是通的,再解释你观察到的东西。**
4. **在冒险的调用之前就把这一步写进库**(`?probe=aura` / `?probe=chain` 的面包屑)。哪怕后来证明 worker 没被杀,这套面包屑还是把三天的猜测变成了一行写着 429 的日志。

**三个 provider,按"有没有 key"自动选**(因为"最好听的"和"不需要国外信用卡的"不是同一个):
| | 配了 `OPENAI_API_KEY` | 什么都没配(默认) |
|---|---|---|
| 用谁 | **ElevenLabs**(有 `ELEVENLABS_API_KEY` 时优先于一切)/ `gpt-4o-mini-tts` | **Cloudflare Workers AI**(`@cf/deepgram/aura-2-en`,失败退回 `aura-1`) |
| 表演指示 | ✅ 支持,`DELIVERY` 生效 | ❌ **完全不支持**,情绪只能靠选角承担 |
| 语言 | 多语种 | 偏英语,中文等会明显变差 |
| 花钱 | 要卡,约 $0.006/条 | **零成本、零注册、已经绑好了** |

- **provider 进 hash**(`providerFor(env)`),所以换 provider 会重新生成,不会把旧音色一直服务下去。实测两种 provider 产生 2 个不同 hash,不撞车。
- Workers AI 的返回形态不确定(`Response` / `ReadableStream` / `ArrayBuffer` / `Uint8Array`),`toBytes()` 四种都归一化——四种都测过。
- **"没有断句、没有感情"两个毛病,原因不是同一个**(用户实测反馈):
  1. **断句** —— 大头其实在**输入文本**,不在模型。悄悄话是半夜在一个没有拼写检查的框里打出来的,很多**根本没有标点**,或者用回车代替句号。一个靠标点决定停顿的模型拿到一整串没标点的字,只能一口气念完。`shapeForSpeech()` 只做一件事:**给明显没有结尾标点的行补一个句号**(中文行补「。」)。**只补标点,不发明逗号、省略号或任何情绪**——把作者没写的感情替他写进去,不是我们该做的事。
  2. **感情** —— 换 `aura-1` → **`aura-2-en`**。Deepgram 说 Aura 2 是 context-aware,会"根据文本上下文施加自然的节奏、表现力和语气填充",正好就是缺的这两样。仍然免费、仍然不用卡。aura-2 只有英语(和西班牙语 `aura-2-es`),调用失败自动退回 aura-1。
  3. **天花板要认**:免费档没有"表演指示"这个东西,能做到的上限就是"节奏自然、不像机器",做不到 ElevenLabs 那种"很有触动感"。**那个水准只有付费+可指挥的模型能给**(`OPENAI_API_KEY` 一配上就自动切过去,`DELIVERY` 立刻生效)。
- **ElevenLabs 为什么没接**:免费档 10,000 credits/月(约 25 条),而且**免费档没有商用授权、必须署名**——这个站是要商业化的(§7b 已经把"非商业"从免责声明里删掉了),免费档在法律上就不能用。想接的话 `synthesize()` 里加一个分支即可,但要等能付费再说。

- **配了 key 时选 OpenAI `gpt-4o-mini-tts`,没选 ElevenLabs**。理由两条:①它接受一句大白话的表演指示并且真的照做——`src/tts.js` 里 `DELIVERY.pain` 写的是"像在安慰一个坐在你旁边、正在难过的朋友,不急不躁,低而温暖,带一点悲伤,在人会自然换气的地方留白;绝不明亮、绝不轻快";②便宜约 6 倍(一条 400 字的悄悄话约 $0.006)。**倾诉和许愿用两套不同的指示**——它们不该用同一种语气念。
- 想换 ElevenLabs 的话:**只需要重写 `synthesize()` 一个函数**,缓存、接口、前端都不用动。
- **成本天然封顶,不需要限流**:`/api/voice/<id>` 把音频按「文本 + 音色 + 表演指示」的 SHA-256 缓存进 D1 的 `voice_chunks` 表。同一条悄悄话**这辈子只付一次钱**,之后无限次重播都是免费读库。悄悄话是有限的,所以总账也是有限的。改了 `RECIPE`/音色/指示 → hash 变了 → 自动重新生成,不用手动清缓存。
- **⚠️ 音频必须分片存,这是踩过的坑**:**D1 单个 BLOB / 单行上限 2,000,000 字节**,而一分钟语音远不止。第一版一行存一整段,长悄悄话插入必然失败——而那句 insert 我包在 try/catch 里(本意是防并发),于是**失败是静默的**:那条悄悄话每播一次就重新生成、重新收费一次,跟"只付一次"正好相反,而且看不出来。现在按 900KB 分片、用 `DB.batch()` 一次性写入(要么整段进库要么完全不进,半段音频会被当成"完整"永久服务)。
  - **本地 sqlite 不强制这个 2MB 上限**,所以这个 bug 在本地测试里是测不出来的——它是查文档查出来的,不是跑出来的。以后往 D1 里塞任何二进制,先想这一条。
- **格式选 AAC 不是默认的 MP3**:OpenAI 的 MP3 输出约 **2.87MB/分钟**(播音级码率,给一个人轻声念完全是浪费),AAC 在同等听感下小得多;而且不像 Opus,AAC 在 iOS 上原生就能播。
- **存储总量的天花板**:D1 免费版 500MB、付费版 10GB。真到了那一步,和博客图片是同一个搬法——**把字节搬去 R2,`voice_chunks` 退化成索引,`/api/voice/<id>` 这个地址不变**。现在还远没到。
- **隐藏的悄悄话在这里也念不出来**(`hidden = 0` 同款过滤)。否则被举报下架的内容能从音频这条路绕回来被人听见。
- **没配 key 时不许变成坏按钮**:后端返回 `200` + `{error:'not_configured'}`(**不能用 5xx,会被边缘换掉 body**),前端**退回浏览器自带的 `speechSynthesis`**。那是机械音,是安全网不是设计目标。provider 报错同样退回,和 §7c 举报 AI 的 fail-open 是一个态度。
- **⚠️ 安全网自己也要过 iOS 手势那一关,这是同一个坑的第三次**:`speakInBrowser()` 是在 `fetch().then()` 里跑的,手势早没了,而 **iOS 在手势之外调 `speechSynthesis.speak()` 是静默忽略的——不报错、不出声、console 里什么都没有**。于是后端一失败,"安全网"跟着一起哑掉,用户看到的不是"机器音代替了好听的声音",是**彻底没声音**。修法和 `<audio>` 那条一模一样:**在点击里先 `speak()` 一条空 utterance 把权限拿到手**。以后任何"稍后再出声"的入口,都要问一句:发声的那一刻,手势还在吗?
- **音乐做 duck 不做停**:`ambient.js` 的 `duck(on)` 把音量压到 **12%** 当垫底,读完再淡回。人声底下完全静音听起来像坏了。**所有设音量的地方都改走 `vol()`**——否则朗读中途换歌会"啪"地跳回满音量。
- **⚠️ 播放必须在点击的同一个同步栈里发起,这是踩过第二次的坑**:iOS 只允许在用户手势中调 `play()`,**`await` 一下手势就没了**。`ambient.js` 里从写音乐那天起就留着这条警告注释,我做 Listen 时照样踩了——先 `await fetch` 拿 blob、再 `new Audio().play()`,在 iPhone 上就是**一点声音都没有**。**但"直接把 src 指向接口"是另一个坑**:iOS 还要求**媒体 URL 必须支持 HTTP byte-range**,普通 Pages Function 响应不支持,于是照样没声音——我一次踩了两边。**两条同时满足的做法**:点击里先用一段内联静音 WAV 把 `<audio>` 解锁(此后 iOS 允许这个元素再次播放),然后再 fetch 成 Blob 换 src。Blob 在内存里,永远不会发 range 请求。endpoint 也补了 206 支持,免得下次有人直接拿这个 URL 当媒体源。**以后任何新的播放入口,先确认从点击到 `play()` 之间一个 `await` 都没有。**
- **⚠️ 不是 audio 的东西绝不能进缓存**:`ai.run(..., {returnRawResponse:true})` 在模型拒绝时**不一定抛异常**,可能返回一个装着 JSON 错误的正常 Response。上一版把那堆字节当音频存了进去,于是那条悄悄话**永远播不出来**(缓存是永久的)。现在 aura 依次尝试三种调用(aura-2 带 encoding → aura-2 不带 → aura-1),每次都检查 `result.ok`、检查字节数和首字节不是 `{`/`[`;endpoint 入库前再卡一道最小长度。**mime 用模型实际返回的 content-type,不能写死**——第二次尝试不带 `encoding`,模型可能返回 PCM/WAV,标成 `audio/mpeg` 浏览器一样解不出来。
- **排障开关**:地址后加 `?debug=voice`,Listen 的失败原因会直接弹在屏幕上(平时只进 console)。没有这个开关,"还是没声音"这句话里不包含任何可以定位的信息——已经为此白改过两轮。
- **⚠️ iOS 上 `element.volume` 根本不能用,这是踩过的坑**:iPhone 上 `HTMLMediaElement.volume` **写入被忽略、读出来永远是 1**(Apple 把音量留给物理按键,[官方文档](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/Using_HTML5_Audio_Video/Device-SpecificConsiderations/Device-SpecificConsiderations.html))。第一版 duck 和**整套 crossfade** 都是直接写 `element.volume`——**在桌面测试全绿,在 iPhone 上一点效果都没有**,用户实测反馈"背景音乐还是吵,你没调"。现在每个 player 各接一个 **Web Audio `GainNode`**(`createMediaElementSource → gain → destination`),`setLevel(idx, v)` 是唯一的音量入口。**以后任何"调音量"的需求都必须走 gain node,不能碰 `.volume`。**
- **朗读速度在客户端调**(`SPEECH_RATE` + `preservesPitch`),不在生成端调:两个 provider 通用,而且**不会让任何已缓存的音频失效**。
- **⚠️ 长悄悄话"像打机关枪"回来过第二次,而第二次根本不是合成的问题,是缓存**:切片朗读上线后确实修好了,但过几天站主又报同样的毛病。真正的原因在 `voice_errors` 的痕迹里明明白白写着,一连四条:`aura served after: openai: no answer in 20s | gemini: no answer in 20s`。长悄悄话是好几段分别合成的,而中转站给每段的耗时**极不稳定**(实测 3 段 7.6s、7 段 8.0s,也有整体超过 20s 的),当时的超时却是**固定 20s** —— 于是**正在正常工作**的长朗读被掐掉,由 aura 兜底念完。**aura 是"别让人听不到声音"的安全网,不是这个站的声音**,它又平又快,正好就是"机关枪"。
  - **所以要修的是三件事,不是合成**:①超时**按片数增长**(`deadlineFor()`:20s 起,每多一片 +10s,上限 60s)—— 固定上限必然掐掉最长的那些;②**兜底的朗读不再进缓存** —— 缓存是永久的,缓存一次兜底就等于"某一分钟的网络抖动决定了这条悄悄话永远的声音",这就是"明明修好了怎么又坏了"的真相:**不是在重新产生,是在重放**;③`RECIPE` 升到 `v14`,让那批被污染的缓存作废。
  - **查这类问题要用 `?probe=long`,不能只看 `?probe=chain`**:短文本只有 1 片,**任何超时都够用**,所以短探针对"长的坏了"永远报正常 —— 之前就是拿它反复确认"一切正常"。`?probe=long` 用的是接近 `MAX_CHARS` 的整段长文本,还会报 `pieces` 和 `ms`。
  - **Gemini 挪到链尾**:它不是失败,是**挂着** —— 每条朗读都要在它身上白等一个完整超时才轮得到下一家(Google 项目层面直接拒了 `generateContent`)。**失败快的 provider 排在前面不花钱,失败慢的等于把等待时间转嫁给读者。**
- **⚠️ 一条朗读只能有一个人在读 —— "同一条里有两个男声"(2026-08)。** 站主报:长的悄悄话里会出现两个不同的男声。**切片朗读把"一次请求"变成了"每片一次请求",于是所有"换一个再试一次"的逻辑,含义都从"重试"变成了"下半段换个人念"。** 两条路径都改掉了:
  - **音色表每个角色只留一个**(`ELEVEN_PREMADE`:男 Brian、女 Sarah)。原来一个角色备三个 id、被拒就试下一个 —— 单请求时代那是重试,切片之后就是前一片 Brian、后一片 Eric。**兜底不靠这张表,靠六家 provider 的链条**:这里拒了就整条掉到下一家,整条由同一个人念完。
  - **缓存写入要清干净再写**(`cacheReading()`)。`INSERT OR IGNORE` 的主键是 `(hash, part)`,两个人同时点同一条没缓存的悄悄话就会**交错**:先到的占住它有的那些 part,后到的把剩下的 part 补上,读出来是"A 的前半段 + B 的后半段"。**只有超过 900,000 字节(即多于一片)的朗读才会中招,所以正好就是"长的才有问题"。** 现在 DELETE 和 INSERT 放在同一个 `batch()`(D1 的 batch 是事务),两个人抢,赢的那个整条算数。
  - **中转站的音色不再靠"模型名匹配"来决定**(2026-08,站主报"男声还行,女声在长文章里还是两个人")。原来的写法是:模型名像 flux 就用 flux 的音色,**否则回落到 OpenAI 自己的 `ash`/`coral`** —— 而中转站后面挂的是别家模型,它不认识这两个名字,**不认识就自己挑一个,而且不保证两次挑同一个**。长悄悄话是好几次请求,于是同一条里出现两个声音,**我们这边什么都没改**。现在:OpenAI 自己的模型才用 OpenAI 的名字,其余一律按中转站的 id(`flux-cliff-en` / `flux-brooke-en`)去要。**万一模型不是 Flux,会得到一个 400 —— 那是好事**:错误进 `voice_errors`、消息里带合法音色清单,而这期间 Aura 用一个声音把整条念完。**一个会说话的失败,好过一个悄悄换人的声音。**
  - **别再让站主拿手机去点、去念提示给你听 —— `node tools/listen-test.mjs` 自己点。** 真浏览器跑真前端,`/api/*` 全部打桩,不要 key、不要库、不要网。它盯的就是"一条朗读只能有一个人在读"这一条:①一次声都没出过 → 手机自带的声音**应该**接手;②已经出过声之后失败 → **绝对不许**再从头念一遍。实测拿修复前的 `app.js`(3360b72)跑,第二条直接 FAIL,手机的声音把整条从头又念了一遍 —— "长文章里两个声音"就是它。跑之前 `npm i -D playwright`(**故意不写进 package.json**:部署会跑 `npm install`,那会连浏览器一起下)。
  - **`?probe=1` 现在直接报 `relay: { model, gentle_male, warm_female }`** —— 线上到底会用哪两个音色,从外面只有这一个办法看得到。
  - **改 `readInPieces()` 时的硬规矩:任何一片都不许换音色重试。** 一片读不了就让整次尝试失败、让下一家 provider 重念整条 —— 听众听得出中间换人,那比"这次没成功"更糟。
  - **切片从 200 字缩到 140 字**(`CHUNK_CHARS`,站主听完提的:"分得再短一点点,念起来感情饱满一点")。方向和当初做切片是同一个 —— **一次交给对话型模型的字越少,它越接近自己擅长的那种"一轮对话"**。代价要一起记住:每多一片就是**多一次请求**(免费中转站有速率限制)、**多一个拼接口**、**多一次让服务商换个声音的机会**;超时已经按片数增长,所以这是拿额度和拼接口换语气,**别再往 60 字那种方向调**。
  - **⚠️ 改切片长度必须同时升 `RECIPE`**:切片长度**不进 hash**,所以已经缓存过的朗读会永远保留旧的切法,新设置只对"还没人听过的悄悄话"生效 —— 等于只改了半个站。v15 就是为这个升的。
  - **升 `RECIPE` 之前先数一下再决定,别凭印象**:`?probe=1` 的 `cached` 报的是 `readings / chunks / bytes`。2026-08 实测 **55 条、9.3MB、每条 1 片**,重新生成一遍是笔小钱;上面那句"别随手改缓存键"是在没人数过的时候写的。
  - **旧缓存要清**,否则修好了也还是在重放坏的。这次没有升 `RECIPE`(那会让全站朗读全部重新生成),而是 `migrations/0013_voice_unsplice.sql` **只删多片的那些**:整条整条地删(删一半等于把朗读截断),并且用 2026-08-16 这个固定时间点兜住 —— 迁移每次部署都会重跑,不加这道限制它会一直删长朗读。
- **"像从很远的地方传来"是混响,不是换模型**:所有 TTS 交回来的都是贴着麦克风录的干声,那种空间感是**事后加的**。app.js 的 `addSpace()` 拿 `ambient.audioContext()` 借来同一个 context(别再新建第二个——那个已经被音乐解锁、也已经有 resume 看门狗),接一个 `ConvolverNode`,冲激响应就是一段按 `pow(1-i/n, 2.6)` 衰减的噪声(2.4s),湿声 26%。`?reverb=off` 可以关掉做 A/B。
  - **⚠️ 干声那条线必须先接,这是"装饰不能变成静音"的硬规矩**:`createMediaElementSource()` 是**不可逆**的——元素一旦进了 Web Audio,就再也回不到直接输出。所以 `addSpace()` 里先把 `source → dry(gain=1) → destination` 接通、再去建混响那一半;混响挂了顶多没有空间感,而顺序反过来一挂就是**彻底没声音**。这个项目已经因为"一个装饰把整个功能弄哑"栽过一次了。
  - 建图也在点击的同一个同步栈里(和上面 `play()` 那条同一个原因),`speechRouted` 保证只接一次。
- **Listen 按钮在顶部悬浮**(`.listen-dock`),不在底部动作栏——放底部时它是"一屏之外的第三个按钮",而它本来是给不想读字的人准备的替代入口。带 `×` 可以关掉(关掉只对当前这条生效,下一条还会出现)。
- **"留下一点温度"那句话延后出现**:开场就摆在那儿会被当成装饰完全略过(用户原话:"人家根本没注意到这什么意思")。现在等升起动画走到约 72%(最多 24 秒)才淡入,带一个**持续跳动的 ↓ 箭头**,同时"留言"按钮开始呼吸式发光。请求别人回应,得先让人把话读完。
- **声音不能活得比它所属的视图久**:关阅读页、切到另一颗气球、页面被切到后台,三处都调 `stopSpeaking()`。
- **布局**:三个按钮在 390px 手机上放不下一行(91+146+157+间距 = 418px)。DOM 顺序决定折行位置,所以排成「听 + 留一点光」一行(两种安静的接收方式),「留言」自己占一行(唯一要求你动手写的动作)。

**测出来的坑**:`speechSynthesis.speak()` 在某些平台会直接抛异常,而我第一版没接住——按钮会永远停在"停止"、音乐永远压着,读者除了关掉没别的出路。已经包了 try/catch。
> 环境限制:Playwright 自带 Chromium **没有 MP3 解码器**(和 §7e 的 H.264 同一个专有编解码缺口),所以本地测的是"状态机 + 缓存 + 降级链",**真实音色必须在真机上听**。

## 7g. 作者身份与删除(P0-0 / P0-1)—— ✅ 已上线(2026-08)

**为什么必须先做这个:以前这个站没有"作者"。** `bubbles.code` 是用户自己取的**公开名字**(0003 特意去掉了 UNIQUE,一个名字可以有很多条),而"找一找"把某个名字下的全部悄悄话交给任何输入它的人。"我的内容"只是浏览器 localStorage 里的一串 id,**服务端一无所知**。所以 PRD 里的"作者可以删除""只有作者能站外分享"在旧结构上**做不了**,Apple 要的"阻断滥用者"也无从谈起。

**方案:一台设备一个秘密,不做账号。**
- 第一次发布时前端生成一串 20 位密钥(Crockford 字母表,去掉了 I/L/O/U,抄错就少一半),存在本机;数据库只存 `author_hash = SHA-256(密钥)`。
- **秘密只在"改东西"的时候发**(发布、删除);**读的时候发的是哈希**(`x-author` 头),服务端拿它回答"这条是不是你的"(`mine`)。哈希被人看到也没用,但**哈希绝不回传给客户端**——它能把同一个人写的悄悄话串起来,而这个站的价值就是没人能串。
- **恢复码只在第一条悄悄话的确认页出现一次**,文案直说:没有账号也没有邮箱,丢了就再也删不掉自己的东西。以后每条都弹就成了噪音。
- **老内容(`author_hash IS NULL`)不允许"认领"**:谁都能拿一串新密钥去认领,就等于谁都能删别人的旧悄悄话。它们只能由站主在后台处理。这是历史包袱,不是设计。
- **"找一找"不再把结果记成"我的"**(原来 `renderFindResults()` 里对每条调 `rememberMyBubble`)。名字是印在每条悄悄话下面的公开署名,看得到就能认领 = 谁都能冒充。

**删除**
- 作者删自己的气球:`hidden = 1` + `deleted_at`,所以**所有现有读路径(天空、详情、回复、搜索、朗读)一行都不用改**就看不见了。
- **朗读缓存一并删掉**(`voice_chunks`),音频是文字的副本,不能留在库里。
- **气球的作者删不掉别人写的回复**——那是别人的话。回复只能由写它的人自己删(`DELETE /api/replies/:id`),删的时候把 `warmth` 减回去,否则天空里那条会显示得比实际更暖。
- 别人的和"老的没有作者"的,**返回同一个 403**。区分开就等于给人一个探测器,专找没有保护的悄悄话。

**为什么不是 `content_status`(PRD §12 建议的那个)**:那要动每一条读语句的 `WHERE hidden = 0`,而这一轮只需要区分"作者撤回"和"被举报隐藏",`deleted_at` 就够了。等做举报队列(P0-5)真正需要 `moderation_hold` 时再上,那时才知道字段该长什么样。

**⚠️ 改这块之前先跑 `node tools/identity-test.mjs`**:它用真浏览器验四件事——发布带不带密钥、恢复码只出现一次、删除按钮跟不跟服务端的 `mine` 走、以及**查名字不会把别人的悄悄话记成自己的**。最后那条没有单元测试能抓,它只存在于界面给不给你这个按钮。

## 7h. 举报队列与后台处置(P0-5)—— ✅ 已上线(2026-08)

**以前举报只是一个数字**(`report_count + 1`,到 3 就隐藏)。这够让天空保持干净,**不够运营一个会把人的话删掉的地方**:没人看得到举报了什么、为什么、有没有人看过、最后怎么定的。Apple 上架要求的正是这一条("能举报、并且及时处理"),站主要回答"我的悄悄话为什么不见了"时也需要它。

- **`reports` 表:一条举报一行,处理完也不删。** 两条自动路径(AI 判定、3 次兜底)也写进来,`auto` 字段记是哪一条触发的 —— **"机器隐藏的"和"人同意了"绝不能看起来是同一件事**。
- **没触发隐藏的举报同样入库**:被举报过两次、还挂在天空里的那条,正是应该有人在第三次自动生效之前看一眼的。
- **后台三个动作,只有三个**:`keep`(放回去)/ `hide`(留在库里、从天空拿掉)/ `delete`(再把正文清空)。**`keep` 只会取消"审核隐藏",不会把作者自己删掉的内容放回来**——那个决定不是我们的。
- **处理一条 = 处理该内容全部未决举报**,否则同一条悄悄话要审五遍。
- 队列里直接显示被举报的原文(包括已经隐藏的),**要人另外去查一遍的队列不会有人看**。同时显示"作者自己删的"还是"被隐藏的"(靠 `deleted_at` 区分,见 §7g)。
- **⚠️ 举报理由现在前端还没传**(列和后台展示都已就绪,`reason` 为空)。要加就是发举报前弹一个选项列表 + 5 种语言文案,下一轮做。

**顺带补上的:名字查询限速**(`src/rate-limit.js`、`migrations/0016`)。名字在界面上只显示前两个字(`maskName`),读不到全名 —— 但**两个字加上无限次尝试不算锁**,而且名字都是人自己起的、偏好记。现在十分钟 20 次(`/api/bubbles?code=` 和 `/api/bubbles/by-code/<name>` 共用一个桶),超了返回 429,前端提示"过几分钟再试"。
- **用 D1 存计数,不加 KV / Durable Object 绑定**:这是一天用不了几次的动作,一次小写入换"不用新增绑定、不用改仪表盘、部署不多一步"。真变热了再搬,别提前搬。
- **失败一律放行**(和 AI 审核同一种姿态):数据库抖一下不能变成"找不回自己的悄悄话"。

## 7i. 收藏与 My Sky(P0-2)—— ✅ 已上线(2026-08)

**"别人的故事,你可以珍藏;自己的故事,你可以带走"这句话直接决定了数据结构。**

- **收藏只存引用**(`saves` 表:谁 + 什么类型 + 哪个 id),**一个字的正文都不复制**。列表是 JOIN 出来的,所以**作者一删,它同时从所有人的收藏里消失**——不需要清理任务,也没有"忘了跑"的可能。**没有人会拿着一份别人最难熬那晚的永久私人副本。**
- **收藏消失要说出来,不能悄悄少一条**:`/api/me` 返回 `gone`(有几条被作者带走了),前端明说。架子无声变短是很不安的。
- **自己的悄悄话上不显示"收藏"**,已经是你的了。
- **My Sky 用密钥找,不再输名字。** 名字是印在每条下面的公开署名(还只显示前两个字),而密钥不写在任何读者看得见的地方。`GET /api/me` 只收哈希(`x-author`)——**读用哈希,写用密钥**,这条规矩和 §7g 一致。
  - 名字查询**保留在面板下方**:给"恢复码丢了、但还记得自己签的名字"的人用,只能看,不能删。
- **恢复码可以在新设备上粘贴回来**(面板里的"找回我的星空"),这是"换手机"的唯一通路,也是当初决定不做邮箱时就欠下的那一步。

**⚠️ `saves` 是这个产品里第一张"关于人"的表。** 它只存"谁收藏了哪条",**不存浏览记录、不存偏好、不做推荐** —— 这条要守住:一旦服务端开始积累个人档案,这个站就要背上导出/删除/跨境隐私那一整套义务,而它的全部价值是"没人知道我是谁"。

**⚠️ 改这块跑 `node tools/identity-test.mjs`**(现在 11 项):收藏按钮只出现在别人的内容上、My Sky 只发哈希不发密钥、被作者带走的收藏会被明说。

## 7j. 分享卡(P0-4)—— ✅ 已上线(2026-08)

**只有作者本人的内容才有分享入口**(服务端说了算,`bubble.mine`);别人的故事只能站内收藏、回复、点灯。

**卡片在手机本地画,不经过服务器**(`public/js/sharecard.js`,1080×1350 canvas → PNG)。Cloudflare Functions 里没有 canvas,服务端合成要么上付费的 Browser Rendering、要么另起一个渲染服务 —— 那意味着**每张卡都要花钱、还要等一个来回**。本地画:零成本、离线可用、点下去当场出图。走 `navigator.share({files})` 进系统分享面板(这是不接任何一家 SDK 就能到微信 / Instagram 的唯一路),不支持就退回下载。

**长文不做成长图**。超过 220 字只取**开头**(在句号处收口)+ `…` + "读全文 ↓" + 链接。两个理由:①一段停在半路的开头比一堵没人读完的墙传得远;②**卡片是海报,不是副本** —— 全文留在站内,作者随时还能删掉它。
- **不用 AI 挑"最动人的一段"**:那等于让模型给别人的悲伤打分,挑错了比朴素难看得多。开头是写的人自己选的开场。
- 没被截断的短悄悄话**不显示"读全文"** —— 那是卡片在骗自己。

**⚠️ 中文排版:行首不能出现 `。，、！？」`**。贪心折行必然踩这个(`，我不再数日子` 顶在行首,一眼就看得出是按字宽硬切的),所以折完行要把孤立的标点**吊回上一行**(`hangPunctuation()`)。允许它稍微出边界,那是正确做法,比行首标点难看得少得多。

**`?w=<id>` 深链**:卡片上的链接指向具体那一条,打开直接进阅读页。作者删掉之后就是"找不到" —— 卡片作为图片还在,但**回不到那些字**,这正是"可删除"应有的结局。

## 7k. 朗读音频搬去 R2(可选开关,代码已就绪)—— 2026-08

**问题**:音频一直存在 D1 里(切成 900KB 一行),而 D1 是**天空列表和阅读页每次点击都要查的那个库**。§7f 已经为这件事栽过一次——"整站变慢"的根源就是音频和悄悄话挤在一个库里。现在 55 条、9.3MB 还行,**App 上量后这是第一个会炸的地方**。

2. 把 `wrangler.toml` 末尾那三行取消注释,推一次
3. 打开 `?probe=1` 确认 `"store": "r2"`

**⚠️ 存储切换是"看着没事、其实把别人花钱生成的东西弄丢了"那一类改动**,而且没法在线上试(桶得先存在)。所以 `tools/voice-store-test.mjs` 用假的 R2/D1 把两条路都跑一遍,**最要紧的一条是:建桶之前写的朗读,建桶之后还能播**。

## 7m. ⚠️ 一次线上事故:部署显示成功,站点却是坏的(2026-08)

**站主报:新功能一个都看不到,而且发不了气球、打不开气球。** 三个症状同时出现,但天空里的气球照常飘 —— 这个组合本身就是线索。

**根因:一个迁移文件里放了四条 `ALTER TABLE`。** D1 执行 `--file` 是**整个文件一起回滚**的 —— 其中任何一条出问题,四条全都不生效。而部署脚本只在 wrangler 退出码非零时才看输出,于是**数据库半途而废,部署照报成功**,线上就变成"新代码 + 旧表结构":

| 接口 | 结果 | 用户看到 |
|---|---|---|
| `GET /api/bubbles`(天空列表) | 200 —— 它不碰任何新列 | 气球照常飘,看起来一切正常 |
| `POST /api/bubbles` | 500 `server_error` | **发不了气球** |
| `GET /api/bubbles/:id` | 500 `no such column: author_hash` | **打不开气球** |
| 详情接口挂了 | —— | 删除/收藏/分享按钮**永远渲染不出来** |

**⚠️ 以后每个迁移文件只放一条语句。** 一个文件失败就只损失它自己那一条,部署脚本里"duplicate column name 可容忍"也才是按语句生效的。0014 已经拆成 0018–0022 并留了空壳说明。

## 7o. 发布后能看见 / 点得中 / 音乐立刻出声(2026-08)

用户报的是"系统不稳定,有时候好好的,突然就失灵":**发完气球看不见、点气球不打开、点音乐半天没反应**。三件事看着像同一个"不稳定",其实是三个各自独立的原因,而且全都在"手指"和"屏幕回应"之间那一小段时间里 —— 没有一个能被单元测试看见。

**① 发完就不见了。** `pin()` 是在服务器一回话就调用的,**那时候确认弹窗还盖在屏幕上**,气球就在弹窗后面升空,等用户关掉弹窗它已经飘到顶上或者回收了。现在改成:先存进 `state.pendingMine`,**关闭确认弹窗时才放飞**,而且不是随机落位:
- **固定坐中近层**(`SPOTLIGHT_TIER = 2`,28px/s):看得清字,又比最近层慢,在屏幕上待将近半分钟;
- **`pickVisibleX()` 保证落在当前可视范围内** —— `pickFreeX()` 是在"比屏幕宽"的世界里随便挑位置的(`WORLD_SPREAD = 1.3`),作者自己那一只落到屏幕外边就等于没发;
- 加 `.spotlight` 暖色光圈,**只亮这一程**,`launch()` 里用完就删标记 —— 几小时后它再被回收上来时,就只是天上普通的一条。

**② 点气球不打开。** 两个原因叠在一起:
- **拖动判定是 6px**。那是鼠标的容差,不是拇指的:手机上一次正常点击会滑动 10px 左右,于是真点击被当成拖动吞掉了。改成 **12px(平台自己用的 touch slop)**,而且**天空没有比屏幕宽的时候根本不判定为拖动** —— 那时候横向拖动本来就没有可去的地方,判定只会白白吃掉点击。
- **远处的气球只有 24px**。`scale = 0.3 + z*1.0`,一个 70px 的灯笼画到屏幕上只剩三分之一,远低于拇指能稳定点中的 44px。现在每只气球带一个**透明的 `.lantern-hit` 命中环**,`--pad` 在 `seatTouchPad()` 里按**它会缩到的最小尺寸**(`z0 - zAmp`,气球是会呼吸的)算出来,保证任何深度都有 44px 可点。

**③ 阅读页等网络。** `openDetail()` 以前 `await fetch` 之后才画东西,慢网络下点一下一秒多毫无反应,然后要么打开要么无声失败。**气球身上本来就有正文** —— 现在 `onTap` 把整条 whisper 一起传过来,先用它开页,fetch 回来只补"回复 / 是不是你的 / 收没收藏"。同时给这个 fetch **加了 8 秒上限**:一个永远不 settle 的请求,就是"点了什么都没发生"。规则和 §7f 的 Listen 一样 —— **点击和回应之间不许有 await**。

**④ 音乐点了半天没声。** 曲库单曲 1.3MB–18.5MB,**文件没下够就一个音都放不出来**,所以"有时候快有时候慢"= 那一首多大。合成器 pad 是 Web Audio,不要网络不要文件,**现在每次点击都先由它出声**,真正的曲子在底下静音加载,`playing` 事件一到再对切过去(约 1.2 秒溶解,不是 3 秒的换曲淡入 —— pad 已经退下去了,3 秒会留一个洞)。`pickLightTrack()`(只从体积小的那一半里开场)保留,现在是"让等待更短",不再是"唯一的防线"。

**验证:`node tools/sky-feedback-test.mjs`(14 项)、`node tools/music-start-test.mjs`(3 项)。两个都在改之前的代码上是 FAIL 的** —— 音乐那条在旧代码上是 `never`(文件到之前一个音都没有)。

## 7p. 压力测试:唯一会随规模崩掉的是天空那一条查询(2026-08)

`node tools/load-test.mjs`。真实 schema(跑真迁移)、真实语句(从 `functions/` 里抄的原句),本地 SQLite,1k / 10k / 100k / 500k 四个规模。**本地 SQLite 不是 D1**,但查询计划是同一个,所以曲线的形状是可信的;绝对毫秒数不可信(D1 还要加网络和它自己的开销)。

| 悄悄话条数 | 一次天空取样(中位) | 扫过的行 |
|---|---|---|
| 1,000 | 0.5ms | 990 |
| 10,000 | 3.0ms | 9,897 |
| 100,000 | 32.7ms | 98,970 |
| 500,000 | 165ms | 494,846 |

**500 倍的内容 = 336 倍的时间,是线性的:每一次请求都把整张表读了一遍。** 原因写在 `functions/api/bubbles/index.js` 的注释里,而且是故意的 —— 每次请求重掷 `RANDOM()`,才有"每个人看到的天空都不一样"(SKY_FEED §3)。代价是排序键算不出索引,只能全表扫 + 全表排。

**其余全是平的**(在 50 万条上测):打开一条 0.01ms、**一万个人同时打开同一条 0.01ms**(主键查,没有热点行问题)、按名字找 0.24ms、My Sky 0.03ms、传微光 0.01ms、发布 0.96ms。**并发打开同一个气球不是问题,可以放心。**

**所以风险只有一条,而且它是有台阶的**(按 165ms/次 折算):
- 1,000 人同时在看 → 约 13 次/秒 → 已经超过一个数据库能扛的
- 10,000 人 → 约 128 次/秒 → 20 倍于此

**但要到 50 万条内容才这样**。今天站上的量离那还很远,10 万条时是 33ms,还撑得住。**这不是现在要改的东西,是"内容涨到十万条以前必须改掉"的东西。**

**改法(未动手,要先和站主确认,因为这是 CLAUDE.md 点名保护的区域):** 给每条加一个稳定的随机键 `rk` 并建索引,取样改成"随机挑一个点,顺着索引取 40 条,到头绕回开头" —— 每次请求只读 40 行,和总量无关,而且**每个人拿到的仍然不一样**。难点是权重(热度加成、新内容加成、零回复加成)现在算在排序键里,得改成写入时折进 `rk`、或者拆成两个池子(冷启动池 + 普通池)按比例抽。**动之前必须先读 `docs/SKY_FEED.md`,把每一条规则重新对一遍** —— 这里最容易"修好一条、悄悄弄坏另一条"。

**顺手修了一处**:`/api/bubbles/[id]/lights` 以前先 SELECT 再 UPDATE,而 `RETURNING` 在行不存在或已隐藏时本来就返回空 —— 等于在全站点击最多的写入上白跑一趟数据库。现在一条语句。
