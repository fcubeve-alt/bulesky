本文件在上一版《App 化与商业化讨论整理》的基础上继续升级,保留原有 App、My Sky、Listen/TTS、成本与商业化结论,并新增本轮讨论形成的内容权利控制系统:删除、收藏、分享、举报、屏蔽、审核、TTS 权限、站外传播授权,以及"自有内容分享卡/视频"的实现策略。目标是先把 Web 版本升级到可持续、可治理、可迁移到 iOS/Android 的基础状态,再逐步提交 App Store / Google Play。

## 0. 本轮升级的核心结论

- 自己的内容:可以删除、可以分享、可以生成分享卡/视频;平台仍需遵守用户自己的站外授权选择。
- 别人的内容:可以阅读、回复、点灯、站内收藏;默认不能站外分享、下载、导出或商业使用。
- 收藏不是复制所有权:建议保存对原内容的引用。原作者删除后,收藏项随之失效。
- UGC 治理必须补齐:过滤、举报、后台审核队列、违规处置、封禁/阻断滥用者、公开联系渠道。
- My Sky 升级为个人情感空间:My Balloons / Saved / Lights I Left / Responses / Listen Again。
- 分享功能分短文本与长文本:短文本生成品牌分享卡;长文本默认生成"精选片段 + 深链/网址",也可生成短视频。
- 视频分享技术上可行,但第一版不要一上来做复杂视频编辑器。先做模板化自动生成,再进入系统 Share Sheet。
- Web、iOS、Android 共用同一后端数据与权限模型,避免未来重复改造。

## 1. 为什么值得做 App

- Web 与 App 长期共存。网站承担搜索、Blog、社交媒体落地页和低门槛访问;App 负责留存、沉浸体验、Listen、收藏、My Sky 和通知。
- App 的最大价值不是依靠 App Store 自然流量,而是把 TikTok、Instagram、YouTube、Pinterest 等渠道带来的用户留下来。
- 第一版 App 不需要堆几十个功能,核心链路仍然是:天空 → 气球 → 阅读 → Listen → 点灯/温暖回复 → 收藏。

## 2. App 不能只是网站套壳

- 移动端应有明显的 App-like 体验:My Sky、收藏、轻触觉反馈、Listen、回复/点灯记录、适度通知、系统分享等。
- 后台、数据库、气球、回复、审核、音乐、音频等尽量与网站共用。
- 理想结构:同一个后端、同一片"天空",分别从 Web、iOS、Android 进入。

## 3. My Sky 与收藏

- My Sky 不只是 Favorites,而是个人情感空间。
- 建议栏目:My Balloons(我写过的)、Saved Balloons(我收藏的)、Saved Replies(收藏的回复)、Lights I Left(我点亮过的)、Responses I Received(我收到的回应)、Listen Again(我想再次听的)。
- 收藏别人内容只建立站内引用,不等于下载、复制版权、获得转载权或商业使用权。
- 原作者删除内容后,对应收藏应显示"该故事已离开这片天空"或直接失效;不要让收藏者保留一份永久副本。
- 品牌语言可继续使用:Keep the stories that found you.

## 4. Listen / TTS

- Listen 是核心体验,也可能成为长期内容资产,但必须用按需生成控制成本。
- Lazy Generation:用户发布时只存文字;第一次有人主动点 Listen 时生成音频;生成后永久缓存,后续重复播放不再次调用 TTS。
- 不要自动播放。用户点击 Listen 后背景音乐降低,人声成为主层;结束后音乐恢复。
- 所有付费 TTS API 设置每日/月度预算上限和熔断,防止用户增长或恶意请求造成不可控账单。
- 用户内容用于站内 TTS,需要通过 Terms 取得必要的站内处理许可;站外传播或商业化另行授权。

## 5. 内容权利模型(Content Rights Model)

- 用户原创文字原则上仍属于用户。平台只取得运行服务所必要的许可,不因为用户发布就取得全部版权。
- 站内允许的默认行为:展示、阅读、回复、点灯、站内收藏、为 Listen 生成/缓存音频(以条款许可为前提)。
- 站外传播默认不开放给别人。别人写的故事不能由第三方用户一键分享到 TikTok/Instagram/YouTube。
- 平台如要把用户故事用于官方社交媒体、商品、歌曲、广告、商业合集等,需要单独、明确的站外/商业授权。
- 建议保留默认关闭的授权项:Allow my words to travel further。

## 6. 删除功能(必须补齐)

- 作者应能删除自己的气球;作者也应能删除自己写的回复。
- 删除后:主内容停止公开展示;别人 My Sky 中的收藏失效;该内容的公开 TTS 不再提供;分享深链失效;搜索/推荐中移除。
- 如果系统有账号、自动生成 guest account 或正式账户,未来 App 版本需要同时规划账户删除与关联 UGC 删除。
- 删除动作应有二次确认,并明确告诉用户删除后的影响。

## 7. 分享功能:只分享自己的内容

- 平台现有"分享网站"可以继续保留,但新增"Share my balloon / 分享我的气球"。
- 只有作者本人对自己的气球/回复拥有站外分享入口;别人只能站内收藏、回复、点灯。
- 站外分享应带 ARE YOU ALRIGHT 品牌来源和官网/App 深链,但不能让分享者看起来拥有别人的内容。
- 分享入口建议只在"我的内容"视图或作者身份确认后的故事详情页出现。

## 8. 分享内容怎么做:短文本、长文本、视频

这里不要把"分享"理解成复制原文出去,而是把自己的内容制作成一份漂亮的、带品牌来源的分享资产。第一版建议分三种输出,按实现难度逐步开放。

| 类型 | 推荐输出 | 内容策略 | 实现优先级 |
|---|---|---|---|
| 短文本 | 品牌分享卡(PNG/JPG) | 完整显示短句 + 背景 + 热气球 + ARE YOU ALRIGHT + 链接 | P0,先做 |
| 中等文本 | 分享卡 / 多页卡片 | 首屏精选 3–6 行,必要时分页;不把画面塞满 | P1 |
| 长文本 | 精选片段 + 深链 | 默认只分享最有感染力的一小段,点击回站内阅读全文 | P0,先做 |
| 长文本视频 | 9:16 MP4 | 背景视频 + 气球/文字 + 可选 TTS + 音乐;自动模板生成 | P1/P2 |

关键建议:长文本不要默认把全文做成一张超长图片,也不要把整篇全文塞进 15 秒视频。更好的传播逻辑是"分享一个最有力量的片段 → 保留悬念 → 链回原故事"。

## 9. 视频分享是否难?

- 技术上可行,难度中等,不需要人工剪辑。
- 第一版不要开发自由编辑器,而是做模板化生成:选背景 → 选文字片段 → 选择是否启用 TTS → 自动排版字幕 → 混合音乐 → 输出 9:16 MP4。
- Web 端可由后端/渲染服务统一生成;App 端只负责发起生成、预览、调用系统分享面板。
- 生成视频要异步:用户点"Create share video"后进入生成任务,完成后再提供 Preview / Share。
- 必须缓存已生成结果,文本和模板未变化时不要重复渲染,避免浪费算力。
- 分享视频建议默认只允许分享用户自己的内容;平台官方内容走独立素材池。

## 10. 分享产品语言建议

- 自己的气球:Share my balloon
- 自己的回复:Share my words
- 收藏别人:Keep in My Sky / Save to My Sky
- 不要在别人故事上显示 Share 按钮。
- 长内容生成视频入口可叫:Turn this into a little film / Create a share video(后续再定最终品牌文案)。

## 11. 举报、审核、封禁与安全治理

- 发布前继续采用:关键词/规则过滤 → AI 审核 → 必要时人工复核。
- 所有他人气球与他人回复都应提供 Report。
- Report 进入统一后台队列,记录举报原因、内容、作者、时间、处理状态与处理人。
- 后台操作至少包括:保留、隐藏、删除、警告、限制发布、封禁/阻断滥用者。
- App 版必须能阻止持续恶意用户,即使产品不强调实名账号,也需要有可执行的滥用控制机制。
- About / Principles / Privacy / Terms 中保持公开的联系渠道和社区规则。
- 审核日志与普通用户内容分开,必要时保留合规所需的最小安全记录。

## 12. 内容状态与权限字段(建议数据结构)

Claude Code 实现时建议至少建立以下逻辑字段(具体命名可按现有数据库调整):

- `owner_id` / `author_identity`:作者身份或可验证的作者控制标识
- `content_status`:active / deleted / hidden / moderation_hold
- `share_allowed_by_owner`:作者是否允许自己站外分享(通常 true)
- `external_feature_allowed`:是否允许平台官方站外展示
- `commercial_use_allowed`:是否允许商业用途
- `tts_onsite_allowed`:是否允许站内 TTS
- `audio_status`:none / generating / ready / failed
- `report_count` / `moderation_status`:举报与审核状态
- `saved_by_user`:收藏关系独立表,不复制正文
- `created_at` / `deleted_at` / `updated_at`:生命周期

## 13. Apple / Android 上架前必须具备的基础能力

- UGC 过滤机制。
- 举报不良内容并及时处理。
- 对滥用者进行阻断/封禁。
- 公开可联系平台的方式。
- 如果 App 支持创建账户(包括某些自动生成 guest account 的设计),App 内应提供发起账户删除的能力,并处理关联 UGC。
- App 不能只是 WebView 套壳;应体现 My Sky、收藏、Listen、分享、触觉/系统能力等明确的移动端价值。

## 14. 商店与成本路线

- 优先 App Store + Google Play;Samsung/Huawei 等以后按真实用户分布决定。
- Apple Developer Program 约 99 美元/年;Google Play 约 25 美元一次性(最终提交前仍以当时官方页面为准)。
- 真正需严控的是运营成本:数据库、视频/音频存储与流量、AI 审核、TTS、视频渲染。
- 所有按量服务设置预算硬上限、缓存和去重。

## 15. 商业化原则(沿用上一版)

- 核心体验保持免费,不急于强订阅。
- 收入第一层:自愿支持 / Buy Me a Coffee。
- 第二层:My Sky Keepsake、电子纪念册、纪念音频、纪念影片、私人纪念空间。
- 第三层:品牌周边(杯子、笔记本、海报、明信片、书签等),优先按需印刷。
- 第四层:原创治愈音乐、内容收入、品牌合作、克制的 Sponsored Sky。
- 商业收入尽量长在核心体验外围,不侵入一个正在悲伤或倾诉的人面前。

## 16. 原创音乐与内容资产

- 原创文字/授权文字 → 歌词 → AI 辅助作曲 → 评分筛选 → 平台背景音乐/社交视频/音乐流媒体。
- 用户气球不能未经商业授权直接拿去做歌曲或商品。
- 同一份高质量原创内容应在授权清晰的前提下反复复用:文字 → TTS → 视频 → 社媒 → App/Web 导流 → Keepsake。

## 17. 本轮 Claude Code 执行范围(建议作为下一轮升级)

- P0-1:作者删除自己的气球和自己的回复。
- P0-2:收藏别人气球/回复到 My Sky;收藏只存引用,原内容删除后自动失效。
- P0-3:作者分享自己的气球/回复;别人内容不提供站外 Share。
- P0-4:短文本品牌分享卡生成;长文本"精选片段 + 深链"分享。
- P0-5:Report 举报入口 + 后台审核队列 + 隐藏/删除/封禁基本处置。
- P0-6:权限字段与审核状态统一到后端,Web/iOS/Android 共用。
- P0-7:Terms / Principles / Privacy 的相关条款留接口,完成产品实现后再统一审核文字。
- P1-1:模板化 9:16 视频分享生成。
- P1-2:分享视频加入可选 TTS 与音乐,生成后缓存。
- P1-3:My Sky 完整分区、Listen Again、点灯记录。
- P1-4:App 原生分享面板、轻触觉、通知等移动端体验。
- P2:Sponsored Sky、周边、音乐发行等商业化功能,暂不进入本轮开发。

## 18. 验收标准

- 用户能明确区分"我的内容"和"别人的内容"的权限。
- 自己写的内容可以删除和分享;别人写的内容只能站内互动和收藏。
- 收藏不会制造不可撤销的副本,原作者删除后收藏失效。
- 举报入口容易找到,后台有完整的处理状态与违规处置能力。
- 分享短文本时可以生成品牌一致的分享卡;长文本默认分享精选片段而不是塞满全文。
- 视频分享可以模板化、异步生成并缓存,不要求人工剪辑。
- Web 与未来 App 使用同一权限逻辑,不需要在上架前重新设计内容权利系统。
- 核心体验仍然保持 ARE YOU ALRIGHT 的安静、纯净、治愈,而不是变成普通社交媒体。

## 19. 最终产品原则

别人的故事,你可以珍藏;自己的故事,你可以带走。ARE YOU ALRIGHT 不应鼓励对别人的脆弱内容进行二次传播,而应允许用户在平台内部保存那些真正触动自己的故事。作者始终保有对自己内容的控制:可删除、可分享、可决定是否让平台把内容带到更远的地方。

## 20. 执行顺序

1. 先升级现有 Web 的内容权利与安全系统。
2. 完成收藏 / My Sky / 删除 / 举报 / 自有内容分享。
3. 再加入 Listen 按需生成与数据统计(若尚未完成)。
4. 随后实现分享视频模板。
5. 整理 API 与权限模型,供 iOS/Android 共用。
6. 制作 App-like iOS/Android MVP,测试后提交 App Store / Google Play。
7. 商业化功能继续用真实数据验证,不在本轮一次性开发。
