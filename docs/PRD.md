# 心灵星空（暂定名）产品需求文档

一个全球化、极致治愈的匿名心灵树洞 Web App
文档整理日期：2026年7月

## 一、产品定位

一个跨国通用、纯 Web 轻应用，无需用户注册登录，实现绝对匿名。核心目标：

- 通过"扫码直达 + PWA/桌面快捷方式"实现极低获客门槛
- 全球用户共享同一个星空，语言无限制，任何语言都可倾诉、都可回复
- 定位是"小而美"的情怀项目，优先满足创始人自身情感需求，同时验证 Claude 辅助开发的可行性；若能持续运营、帮助更多人，则是额外收获

技术架构说明（重要澄清）：虽然不需要复杂 AI 后端，但由于要实现"全球共享同一个星空"和"气泡寻回"功能，必须要有一个轻量云端数据库，不可能纯靠前端本地存储实现（本地存储只在用户自己设备可见，无法跨用户共享）。好在纯文字内容存储成本极低，可用免费额度覆盖很长时间。

## 二、视觉设计

### 整体基调

- 背景采用深蓝紫渐变（如 #0a0e27 → #1a1040），避免纯黑，保留"宇宙感"同时不失温度
- 装饰性背景星星数量克制、大小不一、稀疏分布，避免铺满显杂乱
- 用户内容气泡与背景装饰星星要有明显视觉区分（气泡更大、带柔和光晕呼吸动画）

### 双重情感磁场

**深蓝星海（痛苦倾诉）**
- 初始：低饱和度幽蓝色（如 #4a6fa5）
- 随"温暖回信"数量增加，逐渐过渡为暖色调金橘光晕（如 #ffb366）
- 冷色到暖色的渐变本身即是情绪疗愈的视觉隐喻

**流星花园（心愿许愿）**
- 初始：微弱橙红小火苗，带拖尾动画
- 随"祝福"数量增加，尾焰变长变亮，最终形成划过星空的"恒星"

### 交互细节建议

- 首页设两个柔和入口（"我想说说心事" / "我想许个愿"），点击后有镜头聚焦式过渡动画，而非生硬跳转
- 移动端点击热区应大于视觉尺寸（如视觉20px，热区做到40px）
- 发布内容采用**底部弹出抽屉（bottom sheet）**交互，符合抖音/小红书类使用习惯
- 输入框需正确适配虚拟键盘弹出，避免遮挡
- 系统提示文案走情绪化表达（如"你的心事已经飘向星空"而非"发布成功"）
- 字体选用圆润/柔和风格，中英文及其他语言均需保证美观度

### 功能入口的"轻量化"处理

- "寻找我的气泡"查询：做成右上角小巧半透明图标，点击后展开输入框，不常驻占用视觉空间
- 打赏入口:"支持这片星空"做成角落极小图标(♡),无常驻文字说明,点击后才展开,拒绝弹窗和强推广告。**不要写成"请我喝咖啡"** —— 那是给作者的人情,而这里要的是站点继续运转的开销,后者更容易开口也更容易答应。

## 三、核心互动机制

1. **发射**：用户选择"倾诉痛苦"或"许下心愿"，输入内容后必须自起一个"专属气泡名/暗号"
   - 建议暗号自动附加随机后缀（如 4 位随机码），降低被他人猜中/碰撞的概率
2. **回信与祝福**：点击任意气泡可阅读内容，并匿名留言回复或祝福
3. **气泡寻回**：输入自己的暗号，精准调出自己的气泡及所有收到的回信/祝福
4. **回复语言不限制**：保留全球用户使用任意语言互相回复的开放性，这是"全球共享星空"概念的魅力所在

## 四、内容安全机制（必须项，非可选）

### 1. 危机干预兜底

- 在"倾诉痛苦"发布页面常驻（不打扰式）提示危机热线信息，如中国大陆用户显示"全国心理援助热线 12356"
- 需准备多语言版本的危机提示语（中/英/西班牙语/阿拉伯语/法语等），根据用户界面语言自动切换

### 2. 关键词过滤（多语言）

- 敏感词库覆盖自杀方式、极端表达等，命中后不阻止发布，但自动附加危机热线提示
- 辱骂/攻击性词汇则直接拦截，不允许发布
- 初期可先做中英文覆盖，其他语言依靠举报机制兜底；后续视规模可考虑接入多语言审核 API

### 3. 联系方式屏蔽（重要，法律责任考量）

避免用户在平台内互留联系方式后私下联系出问题，平台需承担说不清的责任风险。具体拦截规则：

- 电话号码：正则匹配连续 7-15 位数字（覆盖全球不同国家号码位数差异）
- 即时通讯账号关键词：微信/WeChat/加V、WhatsApp、Telegram/TG、Line、Kakao、Instagram/IG、Snapchat、Signal、QQ 等，并根据用户地区持续补充（如中东常用 Telegram，日本常用 Line，东南亚常用 Zalo）
- 邮箱格式：正则匹配 xxx@xxx.xxx 标准格式
- 处理方式：命中后不是禁止发送，而是自动替换为"***"或提示"为保护双方隐私，联系方式已被隐藏"
- 变形规避（谐音、拆字等）无法 100% 拦截，靠举报机制做补充兜底

### 4. 举报与自净机制

- 每条气泡/回复旁设置"举报"按钮
- 达到一定举报次数（如3次）自动隐藏，无需人工24小时审核

### 5. 数据定期清理

- 内容保留半年至一年后自动归档/清除（具体周期待定）
- 意义：控制存储成本 + 保护用户隐私（避免陈年心事被陌生人反复翻阅打扰当事人）

## 五、技术方案

### 技术栈选型：Cloudflare 一站式方案

- **Cloudflare Pages**：托管网页前端文件
- **Cloudflare Workers**：处理后台逻辑（发布气泡、查询暗号、过滤等）
- **Cloudflare D1**：轻量 SQL 数据库，存储气泡与回复内容

选择理由：
- 免费额度宽松，早期几乎零成本
- 全球节点多、访问速度快，契合"全球共享星空"的低延迟需求
- 三项服务同属一家，原生集成，配置和维护成本低，适合非技术背景的独立开发/小团队

### 设备适配

- 安卓：支持标准 PWA 安装提示，一键固定到主屏幕
- iOS：因系统限制，页面内需设计友好的图文/动效引导弹窗，提示用户通过 Safari"分享"按钮 → "添加到主屏幕"
- 注意事项：iOS 的 PWA 无法有效使用推送通知；系统可能主动清理本地缓存数据，不宜过度依赖本地存储

### 多语言支持

- 界面 UI 根据浏览器/系统语言自动检测切换
- 危机提示语等关键安全文案需多语言预备

## 六、商业化

- 界面角落设置克制的"支持这片星空"打赏入口
- 拒绝任何弹窗和强推广告
- 需清楚认知：纯捐赠模式难以覆盖长期成本，需配合前述数据清理策略控制运营成本

## 七、产品竞争与市场认知（讨论纪要）

**需求真实性**：匿名倾诉是被反复验证过的真实情感需求（对标产品：一罐、微博树洞、Soul、Uki 等），但赛道存活率低，核心症结是"冷启动的鸡蛋困境"——没有回复的树洞留不住用户，没有用户就没有回复，容易陷入死循环。

**差异化认知**：纯视觉包装（星空美学）容易被模仿，不构成长期护城河。当前定位为个人情怀项目/技术验证，暂不追求规模化差异化竞争，若后续想扩大，需考虑更垂直的人群定位或独特机制。

**种子内容与冷启动策略**：
1. 上线前由 AI 协助预先生成一批不同情绪基调的示例气泡+温暖回复，避免星空"空城"
2. 创始人自己先真实使用，作为最初内容来源
3. 小范围分享给信任的朋友（如5-10人），保证有真实互动
4. 后续视效果决定是否扩大推广（如联系情感类自媒体做联合推广），非当前必要项

## 八、待确认/后续讨论事项

- 产品最终命名
- 数据保留周期具体定为多久（半年 or 一年）
- 敏感词库的具体内容与多语言覆盖范围
- 是否需要基础的验证码/防刷机制（防止恶意批量灌水）
- 页面原型设计与实际视觉稿确认
- Cloudflare 账号搭建与部署流程

本文档整理自项目讨论过程，作为后续开发的需求依据，可随讨论深入持续更新。
